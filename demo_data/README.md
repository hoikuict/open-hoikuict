# open-hoikuict 100人規模デモデータ

このディレクトリには、定員100人規模の保育園を想定したデモデータを収録しています。すべて架空の情報で、開発、画面確認、デモ、テストデータ設計のために利用できます。

## 重要

- すべてダミーデータです。
- 実在する園児・保護者・職員の情報は含めないでください。
- メールアドレスは `demo.open-hoikuict.example` を使用しています。
- 本番DBに投入しないでください。

## ディレクトリ

```text
demo_data/
  import_compatible/   # 既存インポート機能に合わせたCSV
  full/                # モデルに近い詳細CSV
  summary.json         # 件数、対象期間、注意事項
```

## seed スクリプトで投入

```bash
python -m scripts.seed_demo_100 --wipe-all
```

`--wipe-all` は既存データを削除します。ローカル開発DB以外では使わないでください。

## 既存インポート機能で入れる場合

`import_compatible/` 以下のCSVを次の順で読み込みます。既存インポート画面で新規登録する想定のため、ID列は空欄にしています。

1. `classrooms.csv`
2. `families.csv`
3. `children.csv`
4. `parent_accounts.csv`
5. `parent_child_links.csv`

この方法では、登降園や日次連絡などの詳細データは入りません。

## 整合性の前提

- カレンダー予定は、seed 実行月の前後2か月（合計5か月）に月6件ずつ生成します。
- 登降園記録は、seed 実行日の3か月前から当日までの平日と、曜日にかかわらず実行当日に生成します。
- 保護者連絡も同じ期間に生成し、出席・病欠・私用欠席の内容を出欠確認と一致させます。
- 登園、病欠、私用欠席、未確認を一定割合で混ぜるため、登降園記録とアラートの件数は実行日によって変わります。
- 擬似ランダム値は園児IDと日付から決まるため、同じ期間に再実行しても重複せず、内容も安定します。
- 園児名と保護者アカウント名の同姓同名は、それぞれ最大2組・各2人までに制限しています。
- 延長保育料金ルールと日別料金は、seed スクリプトが登降園記録から生成します。
- `full/` の `created_by` や `reviewed_by` には、ユーザーIDではなく画面表示用の担当者名を入れている列があります。
