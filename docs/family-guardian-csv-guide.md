# 家庭・園児CSVの取り込み

この機能は、既存の緊急連絡表や台帳を活用して家庭と園児を登録するためのものです。
保護者に最初から入力してもらう場合は、これまでどおり子どもの名前とメールアドレスだけで「初回入力を依頼」を使えます。両方の方法を併用できます。

## 1. 最初に準備するもの

- 更新済みのアプリと、園児台帳管理権限のある職員アカウント。
- 取り込み前のデータベースのバックアップ。
- 元の緊急連絡表Excel（`.xlsx`）。原本は保管してください。
- [家庭・園児CSV変換ツール](../tools/family-child-csv-converter.html)。PCに保存し、ChromeまたはEdgeで開きます。

変換ツールはインターネットへ情報を送信せず、ブラウザー内で処理します。ブラウザーを閉じると作業内容は消えます。

アプリの「データ入出力」から「家庭」のテンプレートCSVをダウンロードします。変換ツールの「アプリの対応を確認」で選択してください。保護者①②を含む24列を確認できるまで、CSVの保存はできません。

## 2. Excelを読み込み、内容を確認する

1. 変換ツールでExcelを選択します。「シート1」があれば最初に選ばれます。別名のシートでは、対象シートを選択してください。
2. 入園日など足りない情報を補います。
3. 既にアプリに登録済みの場合は、アプリから出力した家庭CSVと園児CSVも選択します。
4. 家庭の選択、子どもの姓名・カナ・生年月日・クラスを確認します。
5. 保護者①②の姓名・カナ・続柄・メール・電話・勤務先を確認します。表は左右へスクロールできます。

元表の1回答行を1家庭として扱い、その行の1～4人目の子どもを同じ家庭へ紐付けます。姓や住所が同じという理由で別の回答行を統合しません。重複回答は、採用しない回答の園児のチェックをすべて外します。

姓名に区切りがない場合は元の氏名が表示されます。正しい姓・名へ分けて入力してください。電話番号が数値で保存されている場合、先頭の0が欠けている可能性があるため、原本で確認して修正します。0を自動で足すことはありません。

保護者①が空で②だけある場合は、②のまま出力します。メールは任意で、家族共用のメールでもかまいません。続柄が未入力の新しい保護者は「保護者」となります。

## 3. 家庭、園児の順に取り込む

1. 「① 家庭CSVを保存」を押します。
2. アプリの「データ入出力」で「家庭」を選び、保存したCSVを「事前検証」します。
3. 新規・更新件数と「変更する内容」を確認します。同じ家庭の園児と、明示的に紐付いた保護者アカウントへの変更も表示されます。
4. 確認できたら「インポート実行」を押します。
5. 変換ツールで「② 紐づけ付き園児CSVを保存」を押します。
6. アプリで「園児」を選び、事前検証で家庭ID・家庭名・クラス・保護者情報を確認して確定します。
7. 園児詳細の家族プロフィールと、家庭・園児のエクスポート結果を確認します。

家庭CSVを保存した後に家庭の内容を編集した場合は、家庭CSVも保存し直してください。2つのファイルは別々に確定します。家庭が成功し、園児でエラーが出た場合、成功した家庭は残ります。エラーを直し、最新の家庭CSVを読み込んでIDを確認し、園児を再度事前検証します。

同名家庭が複数ある場合、家庭名だけでは選べません。家庭の登録後に出力したCSVから家庭IDを指定してください。外部の回答番号をアプリのIDとして入力しないでください。

## 4. 既存情報を消さないためのルール

| 操作・状態 | 結果 |
| --- | --- |
| CSVの列がない、またはセルが空欄 | 既存値を保持します。削除には使えません |
| 保護者①の電話だけ変えたい | 同じ行に①の姓・名と新しい電話番号を入力します |
| 保護者の氏名が既存の番号と異なる | 確定を止めます。改姓・氏名訂正は家庭編集画面で先に行います |
| 3人目以降の保護者、追加属性 | 保持します |
| 紐付いたアカウントのメールとCSVが異なる | 確定を止めます。メール変更は保護者アカウント画面で行います |
| アカウントが別世帯の住所を持つ | 専用の住所を保持します |
| 独自の保護者情報がある園児を、保護者未登録の家庭へ移動 | 情報を消さず、先に家庭を整備するよう案内します |
| 事前検証後に台帳が更新された | 確定を止め、再検証を求めます |
| 1ファイルの保存途中で失敗 | そのファイルの変更をすべて取り消します |

家庭CSVでアカウント、招待メール、パスワード、ログインID、園児の閲覧権限は作成・変更しません。利用開始時は、園児詳細の対象保護者から「この保護者のアカウントを登録」へ進み、招待先と閲覧できる園児を確認します。

## 5. 今回取り込まない項目

保護者以外の緊急連絡先①～③、緊急連絡順、勤務先部署名、勤務曜日・勤務時間、通勤方法、平熱・血液型・受診同意は対象外です。変換ツールにも表示します。元の緊急連絡表を保管し、これらも移行済みと扱わないでください。

アプリでは未知の列を警告し、同じ列名の重複をエラーにします。CSVはUTF-8またはCP932、Excelは1シートの`.xlsx`に対応します。出力はUTF-8 BOM付きです。CSVをExcelで開き直して上書きすると電話番号やIDの表記が変わることがあるため、保存したCSVをそのままアプリへ渡してください。

## システム管理者向けの補足

現在の確定処理はSQLite構成に対応します。事前検証は台帳を更新しません。確認データは職員とデータ種別に紐付けて非公開ファイルへ保存し、24時間で期限切れとなります。内容のハッシュを検証し、確定時に一度だけ使用します。確定を失敗・中断した場合も再検証してください。

SQLiteの書き込みロック取得後に台帳の状態を再確認し、保存・園児履歴・監査ログをまとめて確定します。競合検出は家庭・園児・保護者・紐付け・クラス・職員の台帳全体を対象とするため、別の家庭の編集でも再検証を求める場合があります。

監査ログは実行者のID・名前・日時・データ種別・件数と、変更対象ID・項目名を記録します。電話番号などの変更値は監査メタデータへ記録しません。園児プロフィールの履歴には既存の履歴機能と同じく実際の変更内容を保存します。
