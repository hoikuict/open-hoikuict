実装と検証は[実装記録](billing-reopen-implementation-2026-11-01.md)を参照。

## 要望・確認済みの事実

ユーザーから「請求入力で一度Zengin作成したら修正できない」と報告。
銀行への提出状況には「まだ銀行へ提出していない」と回答があった。
同じ請求月の金額を直したいと解釈している。実機の金額や出力状態は変更していない。

調査時の更新前の処理は次のとおり。

- Zengin作成時、請求月と対象請求を `exported` にする。銀行提出を記録する前から表入力・明細追加を拒否する。
- 「差し替え」は一時的に `confirmed` に戻した直後、同じ処理の中で再出力する。金額を編集する画面や保存の機会はない。
- 口座情報・金額等に変更がなければ同じファイルを作り直す。差し替え後も月・請求は `exported` のため編集できない。
- 確定取消APIも `confirmed` の月だけが対象で、この状態からは戻せない。
- 出力の `canceled` 状態と取消理由の列はあるが、取消して請求を編集へ戻すサービス・画面は見つからなかった。

本番版 `225ea99d8ca39f773dd9b8e0920bca13854817b5` と、手元の対応する7ファイルのハッシュが一致。
本番接続は配備情報・コードハッシュの読取りだけ。業務DBは読書きしていない。
同じ実装を架空データのメモリ内DBで実行し、作成直後・差し替え後の両方で修正拒否と同一ファイルを確認した。

## 提案する画面・操作

以下はモック提示時の案。2026-11-01の上記回答により、銀行提出前の取消・修正・再作成の流れを合意済みとした。実機の更新完了とは別の状態である。

| 場面 | 表示・操作 | 変更するタイミング |
| --- | --- | --- |
| 最新の有効な出力が作成済み | 管理者に「取消して修正」。請求月・出力履歴・ロックされた入力画面から開く | ボタンを開いただけでは変更しない |
| 確認画面 | 対象月、出力ID、件数、金額、取消理由、銀行未提出のチェック | 理由とチェックが揃い「取消して修正へ進む」で確定 |
| 確認画面の「戻る」・Esc | 元の画面へ戻る | 取消や状態変更をしない |
| 取消確定 | 旧出力を取消済みとして残す。請求月と当該出力の対象請求を編集可能な状態へ戻す | 一つの処理で確定。失敗時はどちらも戻す |
| 修正画面 | 同じ月・元の金額を保持した園児別入力。既存の費目6列、詳細、口座情報を維持 | 入力中は未保存。「保存」で金額を確定 |
| 入力エラー | 入力値を残して理由を表示 | 保存しない |
| 入力画面から移動 | 未保存の値があれば破棄するか確認 | 破棄に同意しなければ移動しない |
| 再作成 | 請求一覧のZengin作成から、新しいID・金額の出力を作る | 保存済みの請求を使用。旧ファイルは更新しない |
| 取消済みの旧出力 | 旧金額・取消理由を履歴表示。再ダウンロード、銀行提出扱い、結果取込は不可 | 履歴は削除しない |
| 銀行提出済み・結果取込済み | 今回の「取消して修正」は表示しない | 直接編集を許可しない |

作成済み出力の「差し替え」は今回の「取消して修正」に置き換える案。
銀行提出済みに残っている既存の差し替えは別の操作であり、今回のモックでは請求修正へ戻す機能を付けない。
自動転送された延長保育料の直接編集禁止も維持する。元データ訂正・再転送は既存の転送操作で行う。
ダウンロード済みファイルを回収したり、銀行の受付を取り消したりする処理ではないことを確認画面に明記する。

## モック・確認方法

- `tools/billing-reopen-preview/`。実機と一致した3つのJinjaテンプレートを使用し、架空の園児・口座・請求に置換した。
- 生成元は `tools/build_billing_reopen_preview.py`。本体ファイルを変更しない。
- 請求表の6費目、個別明細追加の既存項目、口座編集の12項目を保持。サイドメニューは対象外項目を省略した確認用の枠。
- 画面上の「試す状態」で作成済み、修正中の未入力・一部入力・入力済み・エラー、銀行提出済み、結果取込済みを切り替える。
- 取消→金額修正→保存→請求一覧→再作成を操作できる。既存の別月作成・銀行提出後の差し替え等は対象外と表示する。
- 入力はブラウザーのメモリ内だけ。再読込みで初期状態に戻る。銀行向けの実ファイル・本番DB・送信処理には接続しない。
- ブラウザーで12観点を確認：必須確認、戻る、費目・口座項目の保持、同じ月300→500円、旧300円の保持、新500円、取消済みダウンロード不可、提出・取込後のロック、エラーの値保持、入力3状態、スマートフォンの確認画面。

ローカル検証記録：`.local-dev/billing-reopen-20261101/` の `source-verification.json`、`reproduction.json`、`preview-verification.json` と画面画像。
