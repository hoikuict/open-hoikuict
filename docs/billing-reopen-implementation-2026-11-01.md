## 実装した動作

- 管理者に「取消して修正」を表示。請求月・出力履歴・園児別入力・個別入力から同じ確認画面を開く。
- 対象月・出力ID・件数・金額を表示し、取消理由（500文字以内）と銀行未提出のチェックを必須にする。戻る・Escでは状態を変更しない。
- 取消時は旧出力を残し、理由・管理者名・日時を記録。請求月とその出力に紐づく請求を確定済みに戻し、元の金額を維持する。
- 同じ月で金額を修正・保存し、請求一覧から新しいIDのZengin出力を作る。旧出力の金額・明細・口座・設定スナップショットとハッシュは変更しない。
- 取消済みのダウンロード・銀行提出扱い・差し替え・結果取込・再取消をサーバーでも拒否。銀行提出履歴がある月は、差し替え後の新出力が作成済みでも取消による修正解除を許可しない。
- 自動転送明細のロックと入金済みの保護を維持。取消・提出・差し替え・再作成・請求表保存等は請求月単位のDBロックで競合を制御し、取消途中の失敗は全変更を巻き戻す。
- 表入力のエラー時に入力値を残し、未保存の移動には確認を表示する。小数をエラー表示した後に整数へ直して保存できるよう、数値欄のブラウザーのstep基準に依存せずサーバーで整数を検証する。

Zengin出力に `canceled_by` と `canceled_at` のnullable列を追加する移行処理を設けた。既存の `canceled_reason` を使用し、過去の取消履歴へ架空の操作人・日時を補わない。銀行側の受付取消や、既にダウンロードしたファイルの回収は行わない。

本番基準コピーのバックアップ検査定義は `billing-reopen-20261101`。共有ルートは既存の `plan_documents` の列構成が異なるため、別の `development-billing-reopen-20261101` を使用する。本番用の定義を開発用に弱めず、旧 `production-20261101` 等の定義も変更せず残した。取得形式の設定は変更せず、実機は形式1のままである。
