# 園内接続を一つずつ案内する変更案

2026-09-23。実インストーラーの「園内で使うアドレスを設定」を試用中、利用者から「もっと丁寧に解説しながらステップごとに」と指摘。LAN案内とGmail案内の操作モックを試用後、「OKこれで進めよう」と実装の承認を受けた。配布候補を作成・検証する。公開配布は別途依頼に従う。

## 要望と解釈

- 要望：ネットワークに詳しくない導入担当者が、目的と操作を理解しながら進められること。
- 解釈：文章を一画面に追加するだけでなく、現行の園内接続を8つの小さな手順へ分割する。自動で調べる情報、本人が確認すること、ルーターや管理業者で行うことを明示する。
- 基準：実際に試用した v2026.9.23.2 候補（43c3ab9）の `beta_setup/ui/views.js` と利用者の画面。前後のPC確認・メール・バックアップ・適用・動作確認の入力も残す。
- 未確定：ルーター機種別の案内範囲。利用先の機種・DNS機能・端末OSは未確認なので、特定機種の設定画面があると断定しない。対応していない場合は、入力を保持して担当者へ依頼できる。

## 操作案

1. **準備の見通し**：この作業でできること、アプリと人の分担、必要な管理情報。
2. **園の接続を確認**：選択済みの接続、現在のIP、園内範囲を読み取り候補として提示。元のIP/CIDR入力は「担当者向けの変更」に残す。架空の検出結果と実測を混同しない。
3. **PCの住所を固定**：IPが変わると困る理由、ルーターでの予約、設定値、完了の判断。予約自体の成功はアプリが断定しない。
4. **アドレスの方式を選ぶ**：ドメイン方式と園内専用方式を準備・端末の作業・将来の園外利用で比較。最初からどちらかを選択しない。「わからない」から相談内容を表示できる。
5. **開く名前を決める**：必要なホスト名だけ入力し、完成するURLを表示。園用ドメイン方式はCloudflareでの管理を確認する。
6. **暗号化の準備**：ドメイン方式はCloudflareの限定トークンを、作成画面・権限・対象ドメイン・入力に小分けして案内。園内専用方式は適用後の各端末への証明書登録が必要と説明。
7. **名前とPCを結ぶ**：園内DNSの役割、名前→IPの対応、機種による作業の違い。「分からない」場合の依頼文をその場で生成。
8. **準備を確認**：IP・名前解決・証明書の準備を別々に表示。失敗した項目に戻れる。証明書発行・実際のHTTPS接続は後の適用・動作確認で行うことを区別する。

IP、CIDR、固定確認、HTTPS方式、両方式のホスト名、DNSトークン、DNS設定確認をすべて保持。IP/MAC/ゲートウェイ候補の取得と段階別の確認APIは本実装時の追加作業。端末の信頼登録を簡単な作業と見なして自動完了にはしない。

## 保存・変更・中断

- モックの入力はメモリーのみ。実インストーラーの入力には触れない。ページを閉じると消える。
- 次へ・戻るで入力を保持。中断→再開も現在の手順へ戻る。
- 値の変更後は関連する確認結果を無効化。IP/範囲の変更は固定・DNS確認、ホスト名変更はDNS確認をやり直す。
- 「この接続設定を取り消す」は確認後、今回の園内接続入力だけを開始時へ戻し、導入ホームへ戻る。PC導入状態や他の入力を削除しない。
- ルーター等の外部画面で手動変更した内容は、アプリの中断・取消では戻らないことを説明する。
- 担当者向け依頼文は画面表示のみ。トークン・パスワードを含まず、自動送信しない。

## 追加案：Gmailで送信する場合

利用者の「gmailを使う場合とか入れたらわかりやすくなるかも」を受け、メール画面にも用途別の案内を追加。操作モックの試用を経て、LAN案内と合わせて実装対象として承認済み。

- Gmail／ほかのSMTPの選択 → 送信元 → Googleの2段階認証 → アプリパスワード → 確認メール、の5手順。
- Gmailでは `smtp.gmail.com`、587、STARTTLSを固定値で用意。ログインIDに送信元アドレスを使う。送信元変更時はGoogleの確認とアプリパスワード・送受信確認をやり直す。
- Google Workspaceも説明するが、全アカウントでアプリパスワードを作れるとは扱わない。作れないときは管理者への依頼文を表示できる。
- 通常のGoogleパスワードを入力させず、公式の2段階認証とアプリパスワード案内にリンクする。Gmailの受信（POP/IMAP）設定は変更させない。
- 元のSMTPホスト・ポート・ログインID・秘密情報・送信元・確認用宛先の全情報を保持。Gmailの定型値は確認欄に表示し、ほかのSMTPでは従来どおり入力できる。方式を戻したときに入力を戻せるが、送受信確認は再実行する。
- Gmailの確認メール送信前に送信元・件名・宛先を表示する。サーバー受付と利用者の受信確認を区別する。モックは一切送信しない。
- 「メール・未入力」「Gmail・準備の途中」「Gmail・入力済み」とGmail認証失敗を追加。`http://127.0.0.1:18850/#mail` でメール案内から試せる。

公式資料（2026-09-23確認）：

- [Google：アプリパスワード](https://support.google.com/accounts/answer/185833?hl=ja)
- [Google：2段階認証](https://support.google.com/accounts/answer/185839?hl=ja)
- [Google：SMTP設定値](https://support.google.com/mail/answer/7104828?hl=ja)（送信設定のみ参照。受信設定や旧式の安全性設定は案内しない）
- [Google Workspace：アプリからの送信](https://knowledge.workspace.google.com/admin/gmail/send-email-from-a-printer-scanner-or-app?hl=ja)

## 実装時の保存と確認

手順の位置と秘密情報以外の入力を下書きへ保存する。起動し直した場合は同じ手順から再開できるが、接続の確認結果・受信のチェックは引き継がない。パスワード・トークンと送信方法別のメモリー内入力履歴は下書きに含めない。準備確認は実際のPC情報・名前解決・トークンの参照権限を調べる。メールは送信ボタンを押したときだけ、表示した1宛先へ送る。
