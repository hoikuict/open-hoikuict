# 児童票の翌月作成対応

2026年9月29日の実装記録。当時は開発側へ反映済み・本番未配備。2026年11月1日に[SD-007](spec-decisions.md#sd-007)に基づき[実機へ反映](deployment-child-progress-periods-2026-11-01.md)した。以下の88件の検証は9月29日当時の結果であり、11月1日の再検証は配備記録を参照。

## 実装した動作

- 月次は前月分を初期表示する。10月は9月分、1月は前年12月分、4月は前年度3月分。
- 複数月の周期は直近で終了した期間を初期表示する。3か月周期なら10月・11月とも7〜9月分。
- 一覧・個人履歴・入力画面で対象月を選択できる。年齢別に周期が混在する一覧では、指定月までに終了する各児童の期間を表示する。個人画面の前後ボタンはその児童の周期単位で移動する。
- 一覧の作成状況、新規入力リンク、参考の観察記録は選択期間に連動する。クラス・年齢・状態で絞り込んでも対象月を保持する。
- 既存の5項目を維持し、保存済みの下書き・差戻し票は同じ入力画面で再編集する。帳票詳細の編集リンクからもこの画面へ移動する。レビュー中・承認済みの本文は編集できない。
- 対象期間と実際の作成日時を別に保持する。再編集で対象期間、作成日時、設定版、児童ID、年度を変えない。作成日時は日本時間で表示する。
- 未保存の変更がある状態で期間を切り替える際は、保存して移動／保存せず移動／入力を続ける、を選べる。入力エラーや競合時は本文と根拠の選択を保持する。
- 対象期間に在籍していた退園・卒園児を一覧に含める。入園前・退園後の期間では新規作成を受け付けない。

## 既存データと同時編集

既存票は周期キーだけでなく、児童ID・帳票種別・開始日・終了日で照合する。旧 `manual:` キーで保存された同一期間の児童票も作成済みとして扱う。新規保存時の周期キーはサーバーで日付から決め、クライアントが送ったキーを信用しない。

同じ期間の新規保存が重なった場合は既存の一意制約でも保護する。既存票の編集は現在のロック版と編集履歴の仕組みを使用し、先に保存された内容を上書きしない。

すでに通常キーと手動キーの重複票がある場合は両方を残す。同期間の件数を入力画面で案内し、履歴から各票を確認できる。自動削除・自動統合は行わない。既存票を更新するときに古いキーを書き換える処理もない。

選択した観察記録の変更も編集履歴に残す。保存済みの根拠が後から非表示・取消等になった場合、画面に出ないことだけを理由に既存の根拠を削除しない。

DBのテーブル・列・制約の変更、既存データの一括書換えは不要。

## 維持した運用条件

- クラス表示と編集権限は現在のクラス登録・職員担当設定に基づく。過去のクラス所属や担当権限を自動復元する機能は今回追加していない。
- 退園・卒園児の在籍期間判定には、園児情報の退園日を使用する。退園日が未登録の場合は、日付を推測して過去期間の新規作成を許可しない。
- 周期の計算には現在有効な施設設定を使う。過去票自体の期間・設定版は保持し、履歴から直接開ける。
