# 導入までの進め方

現在は、ローカル認証、保護者登録、Web Pushなどの実装とTrueNASの実機検証が進んでいます。ここでは機能開発の予定ではなく、施設で利用範囲を広げる手順を示します。未実装の機能は[機能と実装状況](features.md)で確認できます。

## 1. 対象業務を決める

登降園、日次連絡、園児台帳など、最初に試す業務と担当者を決めます。使う端末、紙や既存ツールへ残す業務、試行期間、確認する結果を記録します。

## 2. 架空データで流れを試す

[導入方法](getting-started.md)から環境を選び、[日々の業務](daily-work.md)に沿って操作します。保護者の登録・園の承認・ログイン・連絡入力まで確認し、同じ家族でも許可していない園児が見えないことを確かめます。

## 3. サーバーと運用を検証する

[TrueNAS導入ガイド](truenas-beginner-installation-guide.md)と[運用試験仕様の改訂版](pilot-deployment-spec-v2.md)を使います。

| 段階 | 対象 | 確認すること |
| --- | --- | --- |
| A: 技術試験 | 架空データ、管理者と少人数の職員 | HTTPS、認証、権限、保存、更新、バックアップ、隔離復元 |
| B: 業務試験 | 架空データ、1クラス相当 | 2週間以上の業務シナリオ、打刻・料金の照合、紙・電話への切替 |
| C: 限定実データ試験 | 承認した利用者と必要最小限の実データ | 受入条件、移行リハーサル、個人情報の取扱承認、問い合わせ体制 |

アプリに機能があること、ある環境で更新が成功したことだけでは、Cの条件が揃ったとは扱いません。

## 4. 移行範囲と開始条件を確認する

[家庭・園児CSV](family-guardian-csv-guide.md)は、家庭と園児を順に取り込む現在の手順です。[移行元ID・マニフェストを使う一括移行](beta-production-data-migration-spec.md)は別の未実装計画です。必要な移行がどちらに該当するか確認し、未対応の履歴・添付・項目を移行済みとして扱わないでください。

施設内でアカウント停止、保存期間、訂正依頼、障害連絡、バックアップの担当を決め、[リリース・更新時の確認](release-checklist.md)を実施します。

## 5. 限定した範囲から振り返る

利用開始後は紙や既存記録と突き合わせ、連絡漏れ、入力負担、誤打刻、料金差、端末や配送の失敗を記録します。[日常運用](operations.md)を更新し、課題を解消してから利用者・業務の範囲を広げます。
