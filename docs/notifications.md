# 保護者通知

現在の業務通知は、職員が出欠確認から送る **「出欠確認のお願い」** が対象です。アプリ内通知に加え、保護者本人が選んだWeb Push・メールで知らせます。お知らせ・アンケート・日次連絡の更新を一律に自動配信する機能ではありません。

## 受け取り方を選ぶ

| 方法 | 利用条件 | 確認する場所 |
| --- | --- | --- |
| アプリ内通知 | 対象園児に紐付いた有効な保護者アカウント | 保護者ポータル |
| Web Push | サーバーのWeb Push設定、本人の端末登録、ブラウザー許可、プッシュ利用設定 | 保護者の「通知設定」 `/parent-portal/push-settings` |
| メール | メール配送設定、登録メールアドレス、本人がメール通知を有効化 | 同じ通知設定画面 |

メールだけの受信、プッシュとの併用もできます。既存アカウントのメール通知設定は初期値OFFです。業務メール通知の受信設定と、登録・パスワード設定に必要な認証メールは別です。

## 保護者が端末を登録する

1. 施設URLで保護者ポータルへログインし、「通知設定」を開きます。
2. 「この端末で通知を受け取る」を押し、ブラウザーの通知を許可します。
3. 「この端末は登録済み」を確認します。
4. 「プッシュ通知を利用する」をオンにして保存します。
5. 「この端末へテスト通知を送る」で表示とタップ後の遷移を確認します。

テスト通知は操作中の本人端末1台だけが対象で、出欠記録を変更しません。送信は60秒に1回・1日10回まで、期限は5分です。端末側の準備は[本番設定・テスト手順](parent-push-production-setup.md)、端末ごとの記録は[実機確認手順](parent-push-real-device-test.md)を使います。

## 園が確認依頼を送る

出欠確認で対象児を確認し、確認依頼の操作を行います。通知先は有効なアカウントと現在の園児リンクから決まります。送信前にも受信設定・宛先・認可・期限を確認し、取り消された権限や期限切れ通知を配送しない仕組みです。

配送はキューを介して行い、再試行と履歴を保存します。メール配送は既存のメールworkerを使います。通知サービスの受付、端末への表示、通知のクリック、園児の出欠確認はそれぞれ別の状態です。

## 届かない場合

| 症状 | 最初に確認すること |
| --- | --- |
| 端末登録できない | HTTPSの施設URL、ブラウザーの許可、対応する端末の利用方法 |
| 登録済みなのに届かない | プッシュ利用設定、現在端末の購読、アカウントの有効状態、明示的なログアウトの有無 |
| メールだけ届かない | メール受信設定、登録アドレス、迷惑メール、SMTP配送履歴 |
| 通知をタップするとログインが必要 | アプリまたは前段のCloudflare Accessの認証期限 |
| サービス受付済みなのに表示がない | OSの通知設定と実際の表示。受付済みは表示保証ではない |

明示的なログアウトは現在端末の購読を無効化します。セッションの期限切れだけでは購読を無効化しません。届かないことが業務判断へ影響する場合は電話などの代替連絡を使います。

サーバー担当者は[Web Push本番設定](parent-push-production-setup.md)、配送モデルや保持条件は[プッシュ通知仕様](parent-push-notification-spec.md)、メール追加の範囲は[9月11日の変更](spec-improvements-2026-09-11.md)を参照してください。
