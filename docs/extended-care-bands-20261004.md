# 延長保育料金の区分別・時間帯別設定

2026-10-04。操作モックへの合意後、実機検証向けに本番 `744d05fc95afedfffc79c4f93739b08cb38b396e` を基準に実装。

## 画面

- 標準時間・短時間を固定の別枠にし、通常保育 → 前延長 → あと延長 → 適用期間等 → 保存内容確認の順に入力する。
- 前後を使用しない設定と未設定を区別する。時間帯の追加・削除・取消、前後の使用切替後の入力保持、区分ごとの変更取消を備える。
- 適用期間を選んで既存ルールを編集するか、新しい期間を追加できる。期間の重複はサーバーで拒否する。
- 保存前の試算は本計算と共通のサーバー処理を使う。保存エラー・競合エラー時は入力を残す。
- 計算モード、請求連携、従来計算（区分なし）の入力を残す。権限は既存どおり、料金編集は編集権限、モード・請求連携は管理者のみ。
- 過去の料金は保存だけでは変わらない。モックの架空3日表示に代わり、対象月を指定して実データの既存料金一覧で確認・再計算する。

## 計算と互換性

`extended_care_fee_rules.fee_bands_json` と `extended_care_charges.fee_breakdown_json` のnullable列のみ追加する。既存行はNULLのままとし、既存の区分別・従来計算の結果を配備で変更しない。

旧バックアップの復元時は、隔離した復元用コピーにこの2列をNULLで追加する。原本バックアップと稼働DBは準備段階では変更しない。年案など既存の追加移行と組み合わせて復元できる。片方だけの追加、制約・型・無関係な項目の変更は互換として扱わない。新形式から列を持たない旧版への復元は拒否する。

既存ルールは外側の開始・終了が保存されていないため空欄で表示する。時刻を施設で明示して保存すると時間帯別の計算へ移行する。ルール名から区分を推測したり、従来ルールを自動で標準時間へ変えたりしない。

時間帯は同日内で最大24件。重複・途中の空白を禁止し、無料部分は0円の帯とする。課金単位は1〜120分、端数は帯ごとに切り上げる。帯ごとの定額も選択可能。19:00ちょうどの降園では19:00開始の帯は使用していないものとする。猶予は通常保育の境界に前後各1回適用する。日別上限は前後合計に適用する。

時間帯外、使用しない延長での利用、翌日降園は要確認として金額を確定しない。打刻を拒否しない。再計算時に既存の未確定料金がこの状態になったときは古い自動計算行を除いて未算出として表示し、打刻を保持する。確定・調整・対象外・転送済み料金は既存の保護を維持する。

新ルールの更新は内容のリビジョン比較とSQLite書き込みロックを使う。古い編集画面からの上書きを拒否する。CSRF・ログイン確認は既存アプリの保護を使う。
