# 帳票の記入漏れ案内をまとめて確認する試用案

2026-11-15 JST。合意の記録は [SD-056](spec-decisions.md#sd-056)、調査した操作は [指導計画PV-02〜07と追加候補FV-01〜05](staff-manual-findings.md#form-validation-audit-20261115) を参照。

**現在の進め方：一帳票ずつ。** r1.2の試用後、「一つづつ訂正」「まとめてやると導線が混乱する」との指示を受け、複数帳票の同時試用・一括配備という進め方を取りやめた。月案を先に入力→保存→詳細・レビュー依頼→取り下げ・修正まで確認し、「これで実機に反映してみましょう」に基づいて08:40 JSTに配備した。[月案の配備記録](deployment-monthly-validation-2026-11-15.md)。追加のレビュー依頼変更も下記のとおり完了したため、「OK,次の修正候補の帳票に移ろう」を受け、週案（PV-02）の[専用モックr2](weekly-validation-preview-2026-11-15.md)を試用。その後の「これでとりあえず実装しよう」に基づき、週案も実装・ローカル検証を完了した。その後、実機にボタンがないとの指摘を受け、10:38:44 JSTに反映・事後検証を完了した。[週案の配備・検証記録](deployment-weekly-review-2026-11-15.md)。各帳票の操作を合意してから実装・検証し、配備は個別の依頼に従う。下記は横断点検と過去の進行案の記録として残す。

**月案の追加要望（08:40配備後）**　保存の隣にレビュー依頼を追加し、依頼時に計画欄の未記入を止める。評価・反省と行事・活動は対象外という回答を得た。横断モックと分けた月案専用12画面を試用し、「これでいいと思うよ」と合意を得た。[月案モックと合意状態](monthly-review-button-preview-2026-11-15.md)。本実装・検証を終え、09:27:07 JSTに実機反映済み。[追加要望の配備記録](deployment-monthly-review-2026-11-15.md)。この月案の必須条件変更を週案等への合意とは扱わない。

当初は利用者の「その流れで行きましょう」により、対象の整理 → 各帳票のモック試用 → 合意した内容の実装・検証 → 一括配備、を予定したが、進行単位は上記の一帳票ずつへ変更した。日案・月案・週案以外の追加画面は未実装・未配備であり、旧横断モックの存在を個々の仕様合意の根拠にはしない。

## 対象

| 区分 | 試す操作 |
| --- | --- |
| 指導計画 | 週案・月案・年案の保存。0〜5歳の様式と、週をまたぐ作成者不足 |
| 計画の周辺 | 日案・年案の反省下書き／承認確認、承認依頼／差し戻し、日案の実施変更／訂正、園文例の追加／取込、旧式帳票・文書修正 |
| 園児の帳票・記録 | 児童票の保存／保存して切替、子どもの記録の保存／訂正／無効化、健診・身体測定とアレルギーの追加／訂正・更新 |
| 行事・文書 | 行事反省・経緯レコードの作成／改訂、議事録のマーキング／コメント／昇格、文書の確認依頼／差し戻し |

お知らせ・職員アンケート（FV-06）は今回の対象外として残す。旧週案の新規GETは現行週案に移動するため、旧式の確認画面は旧POSTでの入力エラー再表示を基準にした。

## 今回の案

- 押したボタンの直前へ理由をまとめ、入力欄へ移動できるようにする。
- 入力内容を保ち、修正に応じて案内を更新する。別の操作を押したときは、その操作に対応する理由を出す。
- 必須条件と保存・通知のタイミングは維持する。反省の下書きは空欄可、承認確認では本文が必要。年案反省は選択期のいずれかの欄に記入があればよい。承認・確認済みのコメントは任意、差し戻し時は必須。
- 任意欄の空欄を新たにエラーにはしない。測定値の範囲、条件付きの年度・リンク先、園独自の必須欄も案内対象に含める。

## 確認用画面

**r1.2での補完**　月案の「下書きを保存」→「承認・文書情報」→詳細画面の「レビュー依頼」をつないだ。仮保存後に文書リンクが出なかったモックの不備を修正し、0〜5歳の詳細画面を追加して計44画面とした。保存した本文・担任名を同じタブ内で引き継ぎ、依頼・取り下げ・修正まで試せる。月案の担任名もログイン職員名の初期入力を保持し、「担任名を消した場合」を追加。月案の本文全欄を新たに必須にする変更はない。6年齢の導線、通信エラー後の再試行、入力保持と390px幅の近接表示を確認した。このモック補完時点では本実装・配備は未実施（後続の状態は冒頭の配備記録を参照）。

**r1.1での訂正**　週案の新規作成ではログイン中の職員名が自動で入り、保存済みでは記録済みの作成者名を保持する。利用者の指摘を受け、r1で通常の一部入力でも作成者を消していた誤りを修正した。通常4状態は名前を保持し、「作成者を消した場合」だけを追加のエラー試用状態とする。6年齢で自動入力した名前のまま仮保存できることを確認した。実アプリの変更ではない。

`tools/form-validation-preview/` のr1、計38画面。日案の配備版 `8f7bf89d9860300980a4cef781b0561ff845375c` のテンプレート・帳票レンダラーを基準に、既存入力欄を残した架空データの画面を作成した。未入力・一部入力・入力済み・保存エラーを切り替えられる。

この端末の `http://127.0.0.1:8097/` から試用する。モックは本番DB・送信・通知には接続しない。仮保存の確認画面、通信エラーの再試行、一覧への戻り方は試用専用で、本実装の遷移変更案ではない。議事録本文は簡易入力の見本とし、書式・写真・共同編集は今回の試用範囲外。詳しい制約はモックのREADMEに記載した。
