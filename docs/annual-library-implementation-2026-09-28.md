# 既存の年案を引き継ぐ帳票編集

対象は確認済みの1歳児様式（どんぐり年案）から開始する。入口は指導計画トップの「既存の年案を引き継ぐ・開く」、URLは `/plans/annual-library`。旧方式の年案は従来の作成・編集経路を使う。

## できること

- 園ごとに登録された既存年案を選択し、保存前に本文・元セル・元の行・開始位置を確認。
- 各期を横、項目を縦に置いたままセルを自由に編集。BS/Delete、改行、貼り付け、元に戻すに対応。
- 発達の過程は1歳0か月〜2歳11か月、保育士の関わりは年度内4〜3月の軸。位置から推定した開始目安と、職員が確認した開始目安を区別して保存。
- 原文との比較と変更セルの強調。コピー時はコピーした改訂の本文と比較。
- 下書き保存、再表示、既存の申請・承認・差戻し、JSON出力・改訂履歴に接続。
- 前年の同じ様式の年案を新年度へ複製。参照権限のある前年年案だけを候補に表示し、状態も併記。担任名は現在の職員、状態は下書きとして作成する。
- 同年度・園・クラス・年齢による二重作成と、古い版からの上書きを防ぐ。競合時は入力を保持してメッセージを表示。

## データ

`PlanDocument.annual_sheet` と `plan_documents.annual_sheet` に帳票を保存。元データを持つ `source`、編集値の `fields`、比較用の `baseline` を分ける。ブラウザーは本文・開始目安・確認状態だけを送り、出典やセル定義を直接更新できない。

取り込み時は元データのハッシュ、前年複製時は元文書ID・改訂ID・スナップショットのハッシュを保存。元ファイルや前年文書が後で変わっても、保存済み年案の原文と比較基準は変わらない。

`annual_sheet_key` の一意制約と、共通文書の楽観ロックを利用する。SQLiteは書き込みトランザクション内で状態を再確認する。承認済み・申請中の通常編集は不可。共通の旧編集POSTから帳票内容を迂回更新することも防ぐ。

DB起動時にJSON列と一意キー列を追加する。旧年案の本文・期・状態は変換しない。年案JSONは文書の改訂スナップショットとDBバックアップに含まれる。

## 取り込み元の登録

元Excelをそのまま自動判定する汎用インポーターではない。確認済み抽出ツールが出力した `donguri-r8-import-v1` のJSONを使用する。実データはGit管理外の `data/annual/` へ置く。

`data/annual-library-sources.json` に園名とファイルを明示して登録する。次は設定例で、本文データではない。

```json
{
  "実際のHOIKU_NURSERY_REFの値": [
    {"id": "donguri-r8", "path": "C:/python/open-hoikuict/data/annual/donguri-r8-data.json"}
  ]
}
```

環境変数 `HOIKU_ANNUAL_LIBRARY_SOURCES` が設定されている場合は、同じ形式のJSONを環境変数から読む。環境変数が優先。ブラウザーから任意のローカルファイルを指定することはできない。

設定しただけでは業務DBに年案を作らない。利用者が対象年度・クラスと取り込み元を確認して「下書きを保存」した時点で初めて文書を作る。既存文書がある場合はそれを開き、取り込み操作で上書きしない。

保存前は取り込み元ファイルが必要。保存後はDBに原文を保持するため、元ファイルや設定が利用できなくても文書を閲覧・編集できる。

## 検証

```powershell
python -m pytest test_annual_library.py test_plan_docs.py test_monthly_library.py -q
python -m ruff check plan_docs/services/annual_library.py plan_docs/routers/annual_library.py test_annual_library.py tools/annual_library_preview.py
node --check static/js/annual-library.js
```

実画面の検証は、次のコマンドで独立した一時DBとループバック限定サーバーを使う。業務DBは開かない。`--source` を省略すると架空データを使う。

```powershell
python -m tools.annual_library_preview --source data/annual/donguri-r8-data.json --port 8911
```

確認済み：取込前にDBへ保存しない、文字列・改行・未修正の細かな開始位置・原文を保存、削除と再編集、改訂スナップショット、翌年度複製、承認情報の非複製、二重作成・古い版の保存拒否、園・クラス権限、CSRF、不正入力、元データ更新時の拒否、原本がなくなった後の再表示、旧年案の編集、追加マイグレーションの再実行。

ブラウザーではR8どんぐり実データの59編集欄（通常13欄＋配置46文）、未確認45件を確認。BS削除・開始時期変更・確認チェックを保存し、再読み込みでも維持された。前年の微修正済み本文と時期を翌年度プレビューへ引き継ぐことも確認。

## 現時点の範囲

0・2・3・4・5歳児様式と任意Excelの自動判定は未対応。1歳児の確認済み様式に限る。画面の印刷はブラウザー印刷を使い、A3横を指定する。原本と同じ1ページへのPDF・Excel出力は今回の実装対象外。

本番配備・業務DBへの既存年案一括登録・Drive原本の変更は行わない。配備時は既存の最新配備記録と他の未コミット変更を確認する。
