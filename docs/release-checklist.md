# リリース・更新時の確認

機能の実装、配備、実機確認、利用開始の承認を分けて記録します。各項目には対象版、環境、確認者、結果を残してください。このチェックリストの掲載は完了を意味しません。

## コードとドキュメント

- [ ] 更新元・更新先のコミット、変更履歴、既知の制限を確認した。
- [ ] `python -m ruff check .` と、CI条件の `python -m pytest -q --ignore=gen_bunnrei` の結果を確認した。
- [ ] `python -m mkdocs build --strict` と `git diff --check` が通る。
- [ ] 機能一覧・画面一覧・操作ガイド・環境設定が実装と一致する。
- [ ] 公開ファイル、デモ、画面、ログに実データ・秘密値がない。

## 起動・保存・更新

- [ ] productionの必須設定、HTTPS、プロキシの信頼範囲を確認した。
- [ ] 通常起動・Compose・運用スクリプトに業務デモの自動投入がない。
- [ ] 空DBの初期管理者をローカル認証CLIで作り、本人の有効化・ログインを確認した。既存環境では再作成していない。
- [ ] DBコピーによるスキーマ更新リハーサルと、既存データの件数・関係の照合を完了した。
- [ ] DB、施設文例DB、添付（文書確認依頼を含む）が永続化される。
- [ ] 更新前バックアップと復旧先の版・構成を確保し、更新後の `/healthz` と実際の画面操作を確認した。

## 認証・権限・保護者登録

- [ ] 職員ロール、業務別権限、有効状態、担当クラスを職員台帳と照合した。
- [ ] 閲覧専用職員の更新拒否、口座情報の権限、文書確認依頼の閲覧範囲を確認した。
- [ ] 招待・共通QR申請、園による承認先選択、パスワード設定、ログイン、停止・復旧を確認した。
- [ ] 明示した保護者・園児リンクだけが残り、同じ家族の未許可園児を一覧・直接URL・更新操作から扱えない。
- [ ] 再起動・家族編集・CSV取り込みで、園児リンクと保護者情報が意図せず変わらない。
- [ ] MFAなど未実装の機能を利用開始条件にしていない。必要なら導入判定を保留した。

## データ取り込みと業務

- [ ] [家庭・園児CSV](family-guardian-csv-guide.md)で対象項目、既存ID、件数、差分、再取込、失敗時の扱いを確認した。
- [ ] CSV対象外の履歴・添付・項目を移行済みとして扱っていない。
- [ ] 移行元ID・マニフェストによる一括移行が必要な場合は、[未実装計画](beta-production-data-migration-spec.md)の実装とリハーサルを開始条件にした。
- [ ] 登降園、日次連絡、出欠確認、お迎え予定、誤打刻の取消と監査履歴を確認した。
- [ ] 標準時間・短時間の料金ルール、認定期間、課金単位、再計算、確定・請求転送の結果を確認した。
- [ ] お知らせ、アンケートの受付期限、カレンダーの権限、保育記録・計画を対象業務に応じて確認した。

## 通知・端末

- [ ] テスト用宛先で登録メールと管理者復旧メールの配送・期限・再送を確認した。
- [ ] Web Pushを使う場合は[本番設定](parent-push-production-setup.md)と[端末別受入](parent-push-real-device-test.md)を記録した。
- [ ] 出欠確認のメール通知が本人の受信設定に従い、プッシュとの併用・メールのみの受信を確認した。
- [ ] サービス受付と端末表示を区別し、配備時の試験で既存利用者へ意図しない通知を送らない。
- [ ] キオスクの有効化、専用画面、監視時間、無応答時の連絡・復帰を確認した。

## バックアップと運用開始

- [ ] [バックアップ仕様](backup-restore-spec.md)に基づく作成・検証・別系統複製・保持・隔離復元ができる。
- [ ] UIから実行する場合はworkerが稼働し、履歴・検証結果・最終成功日時・スケジュールを確認した。
- [ ] 稼働中workerの試験用途と、正式なバックアップ取得条件を区別した。
- [ ] 復元試験の担当・日程、障害時の紙・電話運用、問い合わせ先を共有した。
- [ ] 個人情報の利用範囲・保存期間・訂正・削除・事故対応を施設で定めた。
- [ ] [運用試験仕様](pilot-deployment-spec-v2.md)に沿って開始する段階と対象者を承認した。
