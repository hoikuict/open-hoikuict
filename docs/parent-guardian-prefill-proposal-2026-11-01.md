# 登録済み保護者情報を招待先の画面へ引き継ぐ

2026-11-01 JST。モック `PARENT-GUARDIAN-PREFILL-MOCK-001`。この会話でユーザーが「この内容で実装」を選択し、下記の画面・動作に合意した。実装・配備状況は[SD-006](spec-decisions.md#sd-006)で追跡する。

## 要望と確認した状態

在園児の保護者追加・招待を本人9項目へ変更した後、ユーザーが台帳と招待先の画面を提示し、「入力し直しになってしまうね」と指摘した。画像の個人情報はモックへ転記していない。

直前に配備・検証した `70fb5dbcbc7577066682b7c7eb8dd017d42c5ec9` を基準に確認した。登録済みの保護者を選んでも、招待先フォームには保護者の初期値を渡していなかった。前回の[SD-005](spec-decisions.md#sd-005)は項目削減を対象とし、登録済み情報の事前表示を含めていなかった。

## 合意した画面と操作

- 「この保護者を招待」：招待時に選んだ保護者本人の姓・名・カナ2項目・続柄・電話・勤務先・勤務先住所・勤務先電話を初期表示する。本人が内容を確認し、変更箇所と不足する必須項目だけ入力して提出する。全部揃っていれば入力し直さずに提出できる。
- 「新しい保護者を追加」：9項目を空欄から入力する。別の保護者の情報を初期値に使わない。
- 項目数・順序・必須6項目／任意3項目は維持する。対象園児は固定表示。新入園・共通QRは従来どおり。
- 入力エラーは本人が修正・消去した値を保持し、台帳の値へ戻さない。
- 提出前に台帳へ保存せず、園の確認・承認後に反映する。任意項目を空欄にしても既存値を削除しない扱いを維持し、削除が必要な場合は園へ知らせる案内を表示する。
- 「入力をやめる」の確認を取り消せば入力を保持し、終了すれば未提出の変更を破棄する。台帳・招待自体は変更しない。リンクから開き直すと登録済みの初期値から再開する。

## 実装時の対象と境界

有効な個別招待を確認した後、招待に保存された保護者枠を使い、招待時の保存内容から本人9項目だけを取り出す。URL・POSTで初期表示先を選ばせず、保護者2・3を保護者1に読み替えない。他の保護者、自宅、健康情報、メール、写真、内部IDなどはこの初期値に含めない。

古い未提出の招待も、本人を特定できる保存内容があれば初期表示する。保存内容が欠けたり対象が曖昧な場合は、別の保護者へ置き換えず空欄にする。招待後に台帳が変わった場合の既存の承認時の競合検知、期限・失効・再招待の検証を維持する。提出済みの旧形式申請には変更を加えない。
