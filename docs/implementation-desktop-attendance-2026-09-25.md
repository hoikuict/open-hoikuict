# 出欠確認のデスクトップ幅の調整

ユーザーがデスクトップの出欠確認について、名前から確認ボタンまでの空白を指摘。
「1列のまま項目を詰めて、名前とボタンを近づける」を選び、
`tools/desktop-attendance-preview/` のモック試用後に「ここも実装して」と依頼した。

## 実装

- 出欠確認の一覧・絞り込み・見出しの最大幅を1,000pxにする。
- 1人1行の並び、名前・状態・登降園時刻・保護者連絡・4状態ボタン・詳細を維持する。
- 文字サイズ・ボタンサイズは維持。狭い画面は既存の折り返し表示を使う。
- 詳細内の4項目は通常2列、640px未満の画面では1列にする。既存の入力・履歴を維持する。
- 適用範囲は出欠確認。共用CSSを使う子どもの名前一覧に幅制限を適用しない。
- CSSの参照バージョンを更新し、旧キャッシュから切り替える。

基準となる本番は `d7df60d658f3d066783c537cd5c26866911d4722`。
今回の業務コード差分はCSSとテンプレート3ファイル。保存処理・DBスキーマの変更なし。
モックの比較メニュー・架空データ・エラー試用設定は業務画面へ取り込まない。

ユーザーの「本番よろ」という依頼に基づき、2026-09-27 05:05 JSTに本番反映を完了。
実機の17テスト、公開サイトの正常応答、新しいCSSの配信を確認した。
配備記録は `docs/deployment-desktop-attendance-2026-09-25.md`。

## 確認

- 関連する既存17テストが成功（出欠確認・コンパクト表示・名前一覧）。
- 架空100人のメモリーDBで実装画面を確認。1861px幅で一覧は1,000px、名前から確認ボタンまで714pxとなり、承認モックと一致した。
- 1861／1366／1024／768／390px幅で横はみ出しなし。園児100人と入力項目を維持。
- 初回入力で理由画面を出さず、選択済みの状態変更では理由を保存し、詳細は閉じたままであることを確認。
- 詳細の4項目はデスクトップで2列になり、比較メニューなどモック専用UIが実装版に含まれないことを確認。

実装版の確認用サーバーは `http://127.0.0.1:8887/attendance-checks/`。
本番DBや実際の通知送信を使わない。
