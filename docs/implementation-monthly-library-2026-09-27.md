## 入口と画面

指導計画ホームと従来の月案作成画面に入口を追加。URLは `/plans/monthly-library`。
保存文書は従来の文書一覧にも表示され、文書詳細から承認・差戻しができる。
従来の月案作成・編集画面は保持している。

- 0〜2歳は共通欄と個人別4列、3〜5歳は養護・教育の4列、食育1枠、右側の月日別行事表。
- 年齢クラスを選択する。誕生日で帳票様式を自動変更しない。
- 個人別行は実在籍に合わせ、0歳6行、1歳7/8行、2歳7/8/7行を繰り返してページ分けする。
- 月齢は対象月初時点の参考表示。暦日・曜日は対象年月から計算する。
- セル内直接編集、候補選択による `○` 付き追記、Backspace/Delete、重複防止、削除後の再選択。
- 候補は年齢・月・区分・項目・領域で絞り込み、全半角正規化とキーワード全語一致で検索。50件ずつ表示。
- 個人と共通の評価反省は分離。食育は `section=食育 OR item=食育`。
- 小さい画面でも表の行列を維持し、帳票内だけ横スクロールする。
- AI設定のない園は未接続を明示。設定した園はOllamaで候補を生成する（上記の追加実装記録を参照）。

## 保存・取消・切り替え

- 「下書きを保存」でサーバーへ保存。自動保存ではない。
- 園・クラスID・年月・年齢クラスごとに一意。新規作成の競合も409で検出。
- 月・クラス・年齢の切り替えでは、画面を開いている間の未保存入力をメモリーに保持する。
- 画面を閉じる・再読み込み・他画面へ移動する場合、未保存入力があれば離脱確認。本文をlocalStorageに保存しない。
- 「保存した内容に戻す」で直前の成功した保存へ戻る。「ひとつ戻す」で編集・追記・復元を取り消せる（30操作）。
- 保存失敗・ログイン切れ・同時編集競合では入力を保持し、成功と表示しない。
- 保存応答後も入力セルを再描画せず、保存中の追加入力とカーソルを保持する。
- 本体の改訂履歴・楽観ロック・承認状態を使用。レビュー中・承認済み等は閲覧専用。
- 下書き後に園児が増えた場合は既存行を残して追加。承認済みの園児構成は固定。

## 保存契約

`plan_documents` にnullableの `monthly_sheet`（JSON）と `monthly_sheet_key` を追加。
既存の月案10項目・個別指導計画は書き換えない。SQLite移行は追加のみで再実行可能。
新しいバックアップ契約 `monthly-library-20260927` を追加し、過去の契約ファイルを保持する。
新契約には、この作業前から存在する開発中スキーマの追加項目も含め、現在の本体と照合している。

帳票JSONはschema_version=1。帳票ID、帳票版 `2026-09-27.1`、クラスID、年齢クラス、
園児参照・表示名・生年月日のスナップショット、フィールドごとの本文と出典を保持。
園と対象年月は文書本体に保持し、JSON出力・改訂スナップショットにも帳票を含める。

| 対象 | フィールドID |
| --- | --- |
| 共通 | `common:goal` / `common:home` / `common:review` / `common:events` |
| 個人 | `child:{children.id}:life|play|help|review` |
| 集団 | `group:{care|health|relations|nature|language|expression}:{goal|environment|expected|support}` |
| 食育 | `group:food` |
| 行事 | `event:{日}`（対象年月と組み合わせる） |

出典はデータソースID、文例ID、原文、原文種別、資料相対パス、シート名、元資料ID、元セルID、
年・月・年齢・項目・区分・領域を保持。元セルIDはExcelのセル座標ではない。
新規出典は保存時にサーバーで検証し、別項目や別園の出典を受け入れない。
既存の出典は、DBが一時利用できなくても保持して手入力を保存できる。

## 過去3か月

文例DBではなく、本体の園児ID付き月案・既存個別指導計画を参照する。
前3暦月を古い順に表示し、年度・進級をまたいでも `child_ref` で追う。
各文書の最新保存版（下書きを含む）を状態と元文書リンク付きで表示する。
同月に複数文書がある場合は、クラス・年齢を明示してそれぞれ表示する。

個人4項目がすべて空白の場合、その園児の月次記録なしと扱う。他月・他園児で補完しない。
旧個別指導計画は4列へ推測変換せず、元の項目名で折りたたみ表示する。
「振り返りの観点」を実施後の評価反省へ移す処理は行わない。

## 文例データソース設定

環境変数 `HOIKU_MONTHLY_LIBRARY_SOURCES` に、園参照をキーとするJSONを設定する。
例（実際の `HOIKU_NURSERY_REF` と一致させる）：

```json
{"ひかり保育園":{"id":"getsuan-20260927","path":"C:/python/getsuan-rag/getsuan.sqlite"}}
```

Linux等では配備先で参照できるパスへ変更する。DBをGitや配備アーカイブへ含めない。
`id` は文例IDの意味が変わる再構築時に更新する。既存の出典スナップショットは保持される。
設定なしでは候補欄に未設定を表示し、手入力と保存は利用可能。
接続は `mode=ro` と `PRAGMA query_only=ON`。取り込み・更新・コピーはしない。
短い検索語と全半角一致を保証するため、年齢・月・欄で絞った本文を正規化して部分一致検索する。

指定実DBで読み取り専用確認済み：1歳10月の生活・健康は先頭50件と続きあり、
「手」の検索も先頭50件、3歳10月の食育は40件。本文・氏名を検査ログへ出力していない。
本番には配備記録のLinux用読み取り専用パスを設定済み。
