# 保護者の連絡項目設定：実装・検証記録

2026-11-16 JST。[SD-057 r2](spec-decisions.md#sd-057-r2)の合意に基づく本実装。実装・隔離環境での検証は完了。同日の配備依頼を受け、2026-11-16 08:05:12 JSTに実機へ反映した。[配備・実機検証記録](deployment-parent-contact-fields-2026-11-16.md)を参照。

## 合意と今回の範囲

利用者の「年齢ごとかクラスごとかで分けて表示する表示しないを選択するほうがわかりやすいと思う」を受けた[モックr2](parent-contact-fields-preview-2026-11-16.md)に対し、「これでいきましょう。わかりやすいです」と合意した。施設で方式を一つ選び、項目は二択とする。r1の引き継ぎ・優先順は使わない。

今回の既存構成は1つのアプリ・DBを1施設として扱い、設定もそのDB内に保持する。モックの施設A／Bの切替は確認専用であり、業務画面へ施設選択を追加しない。複数施設を一つのDBに収容する変更は今回の対象外。

実際の施設でどの年齢から省略するかは未指定。初期状態は全項目表示で、モックの0〜2歳／3〜5歳の見本設定を自動適用しない。

## 操作と保存

- 管理者が「設定 → 保護者の連絡項目」(`/settings/parent-contact-fields`)を開く。閲覧・変更とも、現在も有効な管理者であることをサーバーで確認する。
- 「年齢ごと」「クラスごと」の一つを選び、各表の項目を「表示する／表示しない」で選ぶ。両方の表を保持し、保存した方式だけを使う。
- 「プレビューを更新」は設定を保存しない。架空園児の実際の保護者入力テンプレートを使い、未入力・入力済み・一部入力・エラーを確認できる。iframeのsandboxとCSPにより連絡送信・外部通信を禁止する。
- 「設定を保存」で確定し、変更者・変更前後・版を履歴に記録する。「変更を取り消す」で保存済みの設定に戻る。別の管理者やクラス構成による競合は409で案内する。
- 新しく作成する連絡に設定を適用する。入力画面を開いてから設定や対象区分が変わった場合は、古い画面からの送信を止め、開き直す案内を表示する。

## 表示項目と既存記録

対象は体温、睡眠（就寝・起床・睡眠メモ）、夕食、朝食、排便、機嫌、咳、鼻水、服薬、体調メモの10組。元の入力順、食欲・食べたものなどの詳細項目を保持する。非表示の値はサーバーでも除外し、入力チェック・保存を行わない。

出欠、緊急連絡先、お迎え予定、園への連絡事項、欠席欄は共通。病欠の体温・症状は引き続き必須。表示する出席時体温の37.5℃判定など、既存の入力条件を維持する。

連絡の保存時に表示項目を `DailyContactEntry.extra_data.parent_contact_fields` へ保存し、その後の施設設定変更でも編集項目を維持する。今回の機能以前の連絡は全項目表示として扱い、既存の値を保持する。職員の一覧・詳細、保護者のホーム・履歴では設定対象外を「対象外」として未入力と区別する。

年齢は連絡日の属する年度の4月1日時点で判定し、年度途中に生まれた園児は0歳児とする。これは既存の児童記録に合わせた具体化で、設定画面に明示した。0〜5歳に該当しない、生年月日を判定できない、クラス未所属、設定されていない新規クラスは全項目表示。クラスの削除・再登録で数値IDが再利用されても、作成日時を含む識別で以前の設定を使わない。保存済み連絡には所属変更前の項目を維持する。
