## 今ある情報をどう生かすか

- 11月9日の[配備記録](spec-decisions.md#sd-043)と同じ版（`fe83bfa`）では、職員の入口は **園児一覧 → 詳細 → 家族プロフィール**。自宅電話番号、保護者ごとの「電話番号」「勤務先電話番号」がある。保護者①・②は台帳の表示順で、どこへ先に電話するかは表していない。「電話番号」を自動で「携帯」と決めつけない。
- [家庭・園児CSVガイド](family-guardian-csv-guide.md)では、元表の「保護者以外の緊急連絡先①～③」と「緊急連絡順」は取込対象外。既存の番号は候補に使うが、家族がまだ順番を登録していなければ「いつもの連絡順は未登録」とする。従来の電話番号は引き続き確認できる。
- 配備版の日次連絡には「朝食・食欲」「食べた内容」があり、職員の内容一覧の「食事」も朝食のみ。今回のモックでは前日の夕食も追加し、両方の入力方法をそろえる。以前に記入した量や自由記入の値は元の意味のまま参照できる。[9月の内容一覧の仕様](parent-contact-content-list-proposal-2026-09-28.md)

## 保護者の画面案

1. **普段の連絡順を登録する。** メニューの「緊急時の連絡先」から、電話してほしい相手・電話先・番号を確かめ、上から順に並べて保存する。登録済みの番号は選んで使えるようにする。父母の両方や職場の番号を必須にせず、必要な家庭は「祖母の携帯」なども登録できる。以後は変更するときだけこの画面を開く。
2. **日次連絡で、その日の連絡先を伝える。** 「11月9日の緊急連絡先」のように日付と現在の順番を表示する。「いつもどおり」なら選ぶだけ。変更する日は「今日は変更する」を選ぶ。普段の一覧にない相手にもかけてほしいときは「この日だけの連絡先を追加」を押し、「祖母の携帯」のように誰のどの電話かと、電話番号を入力する。登録済みの連絡先と一緒に、かけてほしい順に並べる。日次連絡の「保存する」が成功した時点で職員に反映する案。エラー時は入力を残し、前回の連絡順を保持する。
3. **きょうだいの分を二度答えなくてよい。** 一人目の連絡が済んだら、二人目には「この日の連絡先は、ご家族から連絡済みです」とその順番を表示する。二人目の食事を保存しても連絡順は変わらない。訂正や取消は、同じ対象日を開いて明示的に変更し、保存する。「いつもの順番に戻す」は普段の順番を確認してから保存する。別の保護者が先に更新していたら、古い画面から上書きせず最新内容を確認してもらう。
4. **食事はお子さまごとに入力する。** 11月9日の連絡なら「11月8日の夕食」「11月9日の朝食」の順に表示する。それぞれ「食欲」を「旺盛／普通／あまりない／ない」から一つ選び、「食べたもの」に料理名などを書く。どちらか一方だけでも保存できる。選択を消せば未入力に戻る。「ない」は保護者が選んだときだけ記録する。訂正は対象のお子さまの同じ日次連絡で行う。

## 職員の画面案

**園児一覧 → その子の「詳細」 → 家族プロフィール** の先頭に「今日の緊急連絡先」を置く。最初にかける相手、電話先、番号を一緒に大きく表示し、つながらなければ次の番号をすぐ読めるようにする。色だけに頼らず、見出しを変える。

| その日の状態 | 職員に見せる内容 |
| --- | --- |
| 変更の連絡がある | **今日は連絡順が変わっています**。対象日・受付時刻・今日の順番と番号を最初に表示する。「いつもの順番」はその下に区別して置く。 |
| 家族が「いつもどおり」と回答した | **今日はいつもどおりです**。その日に確認された順番と番号を表示する。 |
| その日の回答がまだない | **今日の連絡先は未回答です**。登録があれば「いつもの連絡順」として表示する。回答済みとは表示しない。 |
| 使える連絡順が登録されていない | **連絡順は未登録です**。プロフィールにある電話番号を、優先順位を付けずに確認できるようにする。 |

たとえば普段は「① 母の職場、② 父の携帯」の家庭で、11月9日だけ祖母に最初にかけてほしいと連絡があった。姉・弟のどちらの「詳細」でも、「今日は連絡順が変わっています」の下に **① 祖母の携帯（この日だけ） → ② 母の職場 → ③ 父の携帯** と、それぞれの電話番号を表示する。11月10日に新しい回答がなければ「今日の連絡先は未回答です」と普段の2件を表示する。祖母の番号は11月9日分の履歴で確認できる。未来日分を先に保存した場合も、その対象日に表示を切り替える。

夕食は家族プロフィールではなく、職員の **日次連絡 → 内容一覧** の「食事」と各園児の連絡詳細、保護者の連絡履歴に出す。前日の夕食と当日の朝食にはそれぞれ見出しを付ける。追加前の記録には夕食の値を補わない。

## モックに進む前の確認点

- **回答の必須範囲：** 案は、出席・欠席ともにその日の連絡先を伝えられるが、未回答でも体調・欠席連絡は送れること。夕食は出席の連絡で任意とする。欠席への訂正や別のきょうだいの提出だけで、家族の当日変更を消さない。
- **登録と閲覧の範囲：** 普段の順番の登録・訂正を即時反映するか、園の確認を挟むか。家族で共有しても、別居などで情報の共有に制限がある家庭や、お子さまごとに別の連絡先が必要な場合を自動でまとめない。誰に共有・編集を認めるかと、園が例外を扱う方法は実装前に決める。[既存の園児閲覧権限](guardian-account-sync.md)やお迎えの権限は広げない。

## モックで確かめること

- 架空のきょうだい二人と保護者二人で、未登録・未回答・いつもどおり・当日変更・訂正／取消・翌日の表示を試す。通常登録がない家庭には「いつもどおり」を選ばせず、日次連絡は妨げない。
- 祖母の携帯をその日だけ1番目に追加し、きょうだい両方の家族プロフィールに同じ番号と順番が出るかを確認する。番号の訂正と追加の取消を試し、翌日には普段の連絡順に戻ることを確かめる。
- 当日の変更には電話できる番号が最低一つ必要。番号が空のとき、他の家族が先に更新したとき、または保存に失敗したときに、職員に不完全な順番を見せない。過去の日付で確認した順番・番号・更新者・時刻は、後日通常登録を変えても書き換えない。
- 既存の入力欄をすべて残した日次連絡の画面で、夕食と朝食を取り違えないか、片方だけの入力・きょうだい別の入力・編集・履歴表示を試す。職員画面では同じ家族のどの子からも「今日まずどこにかけるか」を迷わず読めることを確かめる。
- 同じモックの日次連絡と「お迎え予定を登録・変更」で、園の閉園時刻より前のお迎え予定だけを入力・保存できるかを試す。「試用設定」で見本の閉園時刻を変更できる。[お迎え予定の追加要望と試用範囲（SD-046）](spec-decisions.md#sd-046)
