# 職員個人ポータル機能仕様

## 1. 目的

職員がログイン後に最初に開く画面として、本人に関係する「今日の予定」「回答が必要なアンケート」「業務連絡」を一画面に集約する。

既存のカレンダー、職員アンケート、職員ルームを個別に開かなくても、勤務開始時や業務の合間に短時間で次の内容を把握できる状態を目指す。

- 今日これから何があるか
- 回答期限が近いアンケートがあるか
- 未確認または重要な業務連絡があるか
- 詳細確認や回答のために、どの画面を開けばよいか

本機能は新しい予定・アンケート・連絡の管理機能を作るものではなく、既存機能から本人向けの情報を抽出して表示する「職員ホーム」とする。

## 2. 基本方針

- ログイン中の職員本人に関係する情報だけを表示する。
- 一画面で全件を読ませず、要点と件数を表示して既存の詳細画面へつなぐ。
- 緊急度、未回答、未読、期限を使って、確認すべき情報を上に表示する。
- ポータルを開いただけでは、アンケート回答済みや業務連絡既読にはしない。
- カレンダーの共有範囲、非公開予定、アンケート対象者など、既存機能の権限判定をそのまま利用する。
- PC、タブレット、スマートフォンで同じ情報を確認できるレスポンシブ画面とする。
- 初期実装では利用者によるカードの並べ替えや表示項目のカスタマイズは扱わない。

## 3. 対象範囲

### 3.1 初期実装対象

| 項目 | 内容 |
| --- | --- |
| 職員ホーム | ログイン中の職員名、日付、要確認件数を表示する |
| 今日の予定 | 本人が閲覧でき、表示対象にしているカレンダーの当日予定を表示する |
| アンケート | 本人が対象となる公開中の職員アンケートを表示する |
| 業務連絡 | 職員ルームの親メッセージをコンパクトに表示する |
| 未読管理 | 業務連絡を職員単位で既読管理する |
| 重要度・確認 | 業務連絡の重要度と、確認必須の状態を扱う |
| 既存画面への導線 | カレンダー、アンケート回答、職員ルームへ遷移できる |
| 空・障害状態 | 対象データがない場合と、一部取得に失敗した場合を明確に表示する |

### 3.2 初期実装対象外

| 項目 | 理由 |
| --- | --- |
| シフト表・打刻・勤怠実績 | 現行モデルに勤務シフトがなく、カレンダー予定とは責務が異なるため |
| 園児ごとの要対応タスク | 個人への担当割当モデルがないため |
| 保護者からの連絡の個人通知 | クラス・担当職員への割当仕様を先に定める必要があるため |
| メール、Slack、Teams等の外部通知 | 認証、送信失敗、再送、通知設定を別途設計する必要があるため |
| カードの並べ替え・非表示 | 初期画面の利用状況を確認してから追加するため |
| 施設別の独自ウィジェット | 共通ポータルの安定後に拡張するため |
| ポータル内での予定編集・アンケート回答 | 入力責務を既存画面に集約するため |

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 職員本人 | 現在の職員セッションに紐づく有効な `users` レコード |
| 要確認 | 未回答アンケート、重要・緊急の未読連絡、確認必須だが未確認の連絡の合計 |
| 今日 | 職員の `users.timezone` における 0:00 以上、翌日 0:00 未満 |
| 今日の予定 | 今日の時間範囲と重なる、本人が閲覧できる予定の発生分 |
| 未回答アンケート | 本人が対象で公開期間内にあり、本人単位の回答がまだない職員アンケート |
| 業務連絡 | 職員ルームに投稿された、返信ではない親メッセージ |
| 既読 | 職員が業務連絡の本文またはスレッドを開いた状態 |
| 確認済み | 確認必須の業務連絡に対し、職員が明示的に「確認しました」を実行した状態 |

## 5. 利用者と権限

### 5.1 利用条件

- `get_current_staff_user` で認証できること。
- セッションの `user_id` に対応する `User` が存在し、`is_active = true` であること。
- 職員レコードを特定できない場合は、職員ログイン画面へ戻す。

### 5.2 権限一覧

| 操作 | 閲覧のみ | 編集可 | 管理者 |
| --- | --- | --- | --- |
| 自分のポータル閲覧 | 可 | 可 | 可 |
| 今日の予定閲覧 | 既存カレンダー権限の範囲で可 | 同左 | 同左 |
| 職員アンケート閲覧・回答 | 対象条件の範囲で可 | 同左 | 同左 |
| 業務連絡閲覧・既読 | 可 | 可 | 可 |
| 業務連絡への確認操作 | 可 | 可 | 可 |
| 業務連絡投稿 | 不可 | 可 | 可 |
| 業務連絡の重要度・確認必須指定 | 不可 | 可 | 可 |

`view_only` でも、自分のアンケート回答、既読、確認済みの登録は行える。これらは園児情報や施設情報の編集ではなく、本人の応答として扱う。

## 6. URL・ナビゲーション

| 用途 | メソッド | パス案 |
| --- | --- | --- |
| 職員個人ポータル | GET | `/staff/portal` |
| 業務連絡を既読にする | POST | `/staff-rooms/messages/{message_id}/read` |
| 業務連絡を確認済みにする | POST | `/staff-rooms/messages/{message_id}/acknowledge` |
| 職員ルームの対象スレッドを開く | GET | `/staff-rooms/?thread={message_id}` |

ナビゲーション変更:

- 職員ログイン成功後の標準遷移先を `/staff/portal` に変更する。
- 職員サイドバーの先頭に「ホーム」を追加する。
- ログイン済み職員がロゴまたはサービス名を押した場合も `/staff/portal` へ遷移する。
- 外部リンクやブックマークから既存画面へ直接入る動作は維持する。
- 保護者ポータルのナビゲーションとセッションには影響させない。

## 7. 画面仕様

### 7.1 画面全体

画面タイトルは「職員ホーム」とする。ページ上部に現在の職員名と日付を表示し、その下に要確認サマリー、今日の予定、アンケート、業務連絡を配置する。

PC表示の構成イメージ:

```text
┌─────────────────────────────────────────────────────┐
│ おはようございます、山田 花子さん    2026年7月26日(日) │
│ [要確認 3件] [次の予定 10:00 職員会議]                │
├──────────────────────────────┬──────────────────────┤
│ 今日の予定                    │ アンケート            │
│  09:00 朝礼                   │ ● 未回答 期限あと2日  │
│  10:00 職員会議               │   研修希望調査 [回答] │
│  終日  夏祭り準備             │ ✓ 回答済み ...        │
│                 [すべて見る] │          [すべて見る] │
├──────────────────────────────┴──────────────────────┤
│ 業務連絡                                            │
│ [重要][未読] 避難訓練の役割分担 ...  10:15 佐藤      │
│ [未読] 明日の持ち物について ...        昨日 鈴木      │
│                                       [すべて見る] │
└─────────────────────────────────────────────────────┘
```

### 7.2 レスポンシブ配置

| 画面幅 | 配置 |
| --- | --- |
| 1024px以上 | 「今日の予定」を7列、「アンケート」を5列、業務連絡を全幅にする |
| 768px以上1024px未満 | 予定とアンケートを同幅2列、業務連絡を全幅にする |
| 768px未満 | 日付、要確認、今日の予定、アンケート、業務連絡の順で1列にする |

横スクロールを発生させない。カード内の本文は必要な行数で省略し、詳細画面へのリンクを残す。

### 7.3 ヘッダー・要確認サマリー

表示項目:

- 挨拶と職員表示名
- 職員のタイムゾーンによる現在日付と曜日
- 要確認件数
- 次の予定。今後の予定がなければ表示しない
- 最終更新時刻

要確認件数には次を含める。

1. 未回答の公開中アンケート
2. 重要または緊急で未読の業務連絡
3. `requires_acknowledgement = true` かつ未確認の業務連絡

同じ業務連絡が 2 と 3 の両方に該当しても1件として数える。通常優先度の未読連絡は、業務連絡カードの未読件数には含めるが、画面上部の要確認件数には含めない。

### 7.4 「今日の予定」カード

#### 表示対象

- `list_calendar_contexts` で本人が参照できるカレンダーを取得する。
- アーカイブ済みカレンダーは除外する。
- `CalendarUserPreference.is_visible = false` のカレンダーは除外する。
- 職員のタイムゾーンで算出した今日の範囲と重なる予定を `list_occurrences` 相当の既存ロジックで取得する。
- 単発予定、終日予定、日をまたぐ予定、繰り返し予定、例外変更を扱う。
- 削除済み・キャンセル済みの予定は除外する。
- 非公開予定は既存の `EventOccurrence.display_title` を利用し、詳細を閲覧できない職員には「予定あり」とだけ表示する。

#### 表示内容

| 項目 | 内容 |
| --- | --- |
| 時刻 | 終日は「終日」、通常予定は開始時刻。日またぎは終了日時も補足する |
| 状態 | 進行中、次の予定、終了を視覚的に区別する |
| タイトル | 閲覧権限を適用した `display_title` |
| カレンダー | 色とカレンダー名。色だけでなく名称も表示する |
| 場所 | 設定され、詳細閲覧権限がある場合のみ表示する |

表示順は、進行中、今後、終了済みの順とし、各グループ内は開始時刻順とする。終日予定は各グループの先頭に置く。初期表示は最大6件とし、超過時は「ほかN件」を表示する。

操作:

- 予定を押すと既存の予定詳細を開く。
- 「すべて見る」で `/calendar?mode=day&date=YYYY-MM-DD` を開く。
- ポータル上では予定の作成、編集、削除を行わない。

空状態は「今日の予定はありません」と表示し、カレンダーを編集できる職員には「予定を追加」へのリンクを表示する。

### 7.5 「アンケート」カード

#### 表示対象

既存の職員アンケート一覧と同じ条件を利用する。

- `Survey.audience_type = staff`
- `Survey.status = published`
- 現在日時が公開期間内
- `all_staff`、`staff_role`、`staff_user` のいずれかで本人が対象
- `equivalent_staff_user_ids` を考慮し、外部連携等で同一職員に複数IDがある場合も回答状態を重複させない

#### 表示内容と並び順

| 優先順 | 状態 | 表示 |
| --- | --- | --- |
| 1 | 未回答かつ期限まで24時間以内 | 「期限間近」、締切日時、回答ボタン |
| 2 | 未回答 | 「未回答」、締切日時、回答ボタン |
| 3 | 回答済み | 「回答済み」、回答日時、確認・編集導線 |

未回答内は締切が早い順、締切なしはその後、回答済みは更新日時の新しい順とする。初期表示は最大4件とし、未回答を回答済みより優先する。

操作:

- 未回答カードまたは「回答する」で `/staff-surveys/{survey_id}` を開く。
- 回答済みカードは既存仕様どおり回答画面を開き、公開期間内であれば内容を確認・更新できる。
- 「すべて見る」で `/staff-surveys/` を開く。

対象アンケートがない場合は「回答が必要なアンケートはありません」と表示する。

### 7.6 「業務連絡」カード

#### 表示対象

- 職員ルームの `Message.parent_message_id IS NULL` である親メッセージを対象とする。
- `deleted_at` があるメッセージは除外する。
- `expires_at` が設定され、現在日時を過ぎたメッセージは除外する。
- 初期実装では全職員を対象とする。職員・役割・クラス単位の配信対象指定は将来拡張とする。

#### 表示内容

| 項目 | 内容 |
| --- | --- |
| 状態 | 未読、既読、確認必須、確認済み |
| 重要度 | 通常、重要、緊急 |
| 本文 | 改行を空白にし、先頭80文字を最大2行で表示する |
| 投稿者 | `author_user_id` の表示名。取得できない既存データは `author_name` |
| 投稿日時 | 当日は時刻、前日は「昨日」、それ以前は月日を表示する |
| 補足 | 添付数、返信数 |

並び順:

1. 未確認の確認必須連絡
2. 未読の緊急連絡
3. 未読の重要連絡
4. その他の未読連絡
5. 既読連絡

同じ区分内では投稿日時の新しい順とする。初期表示は最大5件とし、カード見出しに未読総数を表示する。

操作:

- 連絡を押すと `/staff-rooms/?thread={message_id}` を開く。
- 本文またはスレッドを実際に表示した後、既読登録用POSTを送信する。ポータル一覧の表示だけでは既読にしない。
- 確認必須の場合、本文確認後に「確認しました」を押せる。確認済み日時を記録し、取消操作は設けない。
- 「すべて見る」で `/staff-rooms/` を開く。

業務連絡がない場合は「新しい業務連絡はありません」と表示する。

## 8. データ取得・表示ルール

### 8.1 基準日時

- データベースの日時は既存方針どおりUTCで保存する。
- 今日の境界、表示時刻、曜日は `User.timezone` で計算する。
- タイムゾーンが空または不正な場合は `Asia/Tokyo` を使用する。
- ポータルの1リクエスト内では同一の `now` を使用し、カードごとに時刻がずれないようにする。

### 8.2 件数制限

| カード | 初期表示 | 全件導線 |
| --- | ---: | --- |
| 今日の予定 | 6件 | 当日のカレンダー |
| アンケート | 4件 | 職員アンケート一覧 |
| 業務連絡 | 5件 | 職員ルーム |

要確認件数と未読件数は初期表示件数ではなく、対象となる全件から計算する。99件を超える場合は画面上では `99+` と表示する。

### 8.3 更新

- 初回表示はサーバーサイドレンダリングとする。
- 「更新」ボタンでページ全体を再取得できる。
- 初期実装では自動更新を必須にしない。
- 将来HTMXで部分更新する場合も、入力中のフォームや開いているスレッドを閉じない。

### 8.4 一部取得失敗

一つのカードの取得失敗でポータル全体を500エラーにしない。失敗したカードに「情報を取得できませんでした。再読み込みしてください」と表示し、サーバーログには例外と職員IDを記録する。画面にはスタックトレースやSQLを表示しない。

## 9. データモデル

### 9.1 既存モデルの再利用

| 表・モデル | 用途 |
| --- | --- |
| `users` / `User` | 職員本人、表示名、権限、タイムゾーン |
| `calendars`、`calendar_members`、`calendar_user_preferences` | 閲覧可能・表示対象カレンダーの判定 |
| `events`、`recurrence_rules`、`event_overrides` | 今日の予定と繰り返し予定の算出 |
| `surveys`、`survey_targets`、`survey_answers` | 対象アンケートと回答状態 |
| `messages`、`message_attachments` | 業務連絡本文、添付、返信数 |

ポータル専用の予定・アンケート複製テーブルは作成しない。元機能を正とし、ポータル表示時に集約する。

### 9.2 `messages` 追加カラム

既存の職員ルームを業務連絡として個人別に集約できるよう、次のカラムを追加する。

| カラム | 型 | 初期値 | 内容 |
| --- | --- | --- | --- |
| `author_user_id` | uuid, nullable, FK users.id | null | 投稿者職員。既存行は `author_name` を利用する |
| `priority` | string | `normal` | `normal` / `important` / `urgent` |
| `requires_acknowledgement` | boolean | false | 明示確認を求めるか |
| `expires_at` | datetime, nullable | null | ポータル表示期限。元スレッドは削除しない |

これらは親メッセージでのみ利用する。返信では `priority = normal`、`requires_acknowledgement = false`、`expires_at = null` とする。

### 9.3 `staff_message_reads`

| カラム | 型 | 内容 |
| --- | --- | --- |
| `id` | integer | 主キー |
| `message_id` | integer, FK messages.id | 対象の親メッセージ |
| `staff_user_id` | uuid, FK users.id | 閲覧した職員 |
| `read_at` | datetime | 本文またはスレッドを最初に表示した日時 |
| `acknowledged_at` | datetime, nullable | 「確認しました」を実行した日時 |
| `created_at` | datetime | 作成日時 |
| `updated_at` | datetime | 更新日時 |

制約と更新規則:

- `(message_id, staff_user_id)` に一意制約を設定する。
- `message_id` は親メッセージだけを許可する。アプリケーション層でも検証する。
- 既読POSTは冪等とし、既存の `read_at` を上書きしない。
- 確認POST時に未読なら、同時に `read_at` も設定する。
- 確認必須でないメッセージへの確認POSTは400とする。
- 無効化された職員の履歴は監査のため保持する。

### 9.4 インデックス

最低限、次のインデックスを用意する。

- `messages(parent_message_id, deleted_at, created_at)`
- `messages(priority, requires_acknowledgement, expires_at)`
- `staff_message_reads(staff_user_id, read_at)`
- `staff_message_reads(message_id, staff_user_id)` の一意インデックス

## 10. サーバー構成案

### 10.1 ルーター

`routers/staff_portal.py` を追加し、表示用の集約処理を職員認証ルーターやテンプレートに直接書かない。

```text
GET /staff/portal
  ├─ 現在の職員レコードを解決
  ├─ 今日の開始・終了を算出
  ├─ 今日の予定を取得
  ├─ 対象アンケートと回答状態を取得
  ├─ 業務連絡と本人の既読状態を取得
  └─ templates/staff_portal/home.html を表示
```

### 10.2 サービス責務

`staff_portal_service.py` などに次の読み取り処理を分離する。

- `load_today_occurrences(session, staff_user, now)`
- `load_staff_survey_cards(session, staff_user, now)`
- `load_business_message_cards(session, staff_user, now)`
- `build_attention_summary(...)`

カレンダーとアンケートの対象判定は既存サービスを呼び出し、同じ条件を複製しない。業務連絡カードは必要な既読行、添付数、返信数をまとめて取得し、メッセージごとの追加クエリを発生させない。

### 10.3 テンプレート

```text
templates/staff_portal/home.html
templates/staff_portal/_today_schedule.html
templates/staff_portal/_surveys.html
templates/staff_portal/_business_messages.html
```

部分テンプレートは初期実装でも分割し、将来の部分更新に備える。

## 11. セキュリティ・プライバシー

- すべてのポータル・既読・確認エンドポイントで職員認証を必須にする。
- URLの `staff_user_id` やクエリ文字列で表示対象職員を切り替えない。常にセッションの職員IDを使う。
- 非公開カレンダー予定のタイトル、説明、場所を権限外の職員へ返さない。テンプレートで隠すのではなく、表示モデル作成時に除去する。
- 対象外アンケートは件数にも含めず、IDを直接指定しても404とする。
- 他職員の既読・確認状態は一般職員へ表示しない。
- 既読・確認のPOSTはCSRF保護を適用する。
- 業務連絡本文はHTMLとして解釈せず、既存テンプレートと同様にエスケープする。
- ログには職員IDを記録できるが、非公開予定の本文やアンケート回答内容を出力しない。

## 12. 非機能要件

### 12.1 性能

- 通常データ量でサーバー処理の95パーセンタイルを500ms以内の目標とする。
- 一画面表示のためのDBクエリ数は、データ件数に比例して増えないようにする。
- 目安として、予定1,000件、公開中アンケート100件、業務連絡10,000件がある状態でも初期表示対象をDB側で絞り込む。
- ポータル専用に全メッセージ本文や全アンケート回答を読み込まない。

### 12.2 アクセシビリティ

- キーボードだけで各カードと「すべて見る」へ移動できる。
- 未読、重要、期限間近を色だけで表現せず、テキストラベルを併記する。
- 見出しレベルを `h1`、`h2` の順に保つ。
- フォーカス表示を消さない。
- 主要文字色と背景色はWCAG 2.1 AA相当のコントラストを確保する。
- 画面更新後もスクリーンリーダーへ不要な大量読み上げを発生させない。

### 12.3 可用性・互換性

- JavaScriptが無効でも初期表示と詳細画面への遷移ができる。
- 既読・確認操作後はPOST/Redirect/GETとし、再読み込みによる重複処理を防ぐ。
- 現行サポート対象のSQLiteで動作するマイグレーションを用意する。
- 既存のカレンダー、職員アンケート、職員ルームのURLを変更しない。

## 13. 状態別表示

| 状態 | 表示 |
| --- | --- |
| 全カードにデータあり | 優先順位に従って各カードを表示 |
| 今日の予定なし | 「今日の予定はありません」 |
| 未回答アンケートなし、回答済みあり | 回答済みを最大4件表示し「回答が必要なアンケートはありません」と補足 |
| 対象アンケートなし | 空状態メッセージと一覧導線 |
| 未読業務連絡なし | 最近の既読連絡を表示し「未読はありません」と補足 |
| 業務連絡なし | 空状態メッセージ |
| 一部カード取得失敗 | 他カードは表示し、失敗カードだけ再読込案内 |
| 職員レコードなし・無効 | ログイン画面へ遷移し、ポータル内容を表示しない |

## 14. 受入条件

### 14.1 共通

- [ ] 有効な職員で `/staff/portal` を開くと、本人の表示名と本人のタイムゾーンによる日付が表示される。
- [ ] 未ログインで開くと職員ログイン画面へ遷移する。
- [ ] 職員ログイン成功後の標準遷移先が職員ホームになる。
- [ ] サイドバーから職員ホームへ1操作で戻れる。
- [ ] 360px幅で横スクロールせず、予定、アンケート、業務連絡が縦に表示される。

### 14.2 今日の予定

- [ ] 本人が所属し、表示対象にしている個人・共有カレンダーの当日予定だけが表示される。
- [ ] 繰り返し予定と例外変更が当日の正しい時刻・内容で表示される。
- [ ] 終日予定、進行中予定、今後の予定、終了済み予定が仕様順に並ぶ。
- [ ] 非公開予定を閲覧できない場合、タイトル、説明、場所が漏れず「予定あり」と表示される。
- [ ] 「すべて見る」から当日の日表示を開ける。

### 14.3 アンケート

- [ ] 全職員、本人の役割、本人指定の公開中アンケートだけが表示される。
- [ ] 対象外、下書き、終了済み、公開期間外のアンケートは表示も件数計上もされない。
- [ ] 未回答が回答済みより先に表示され、期限間近が判別できる。
- [ ] 回答後にポータルへ戻ると回答済みに更新され、要確認件数が減る。
- [ ] 回答ボタンから本人用の回答画面を開ける。

### 14.4 業務連絡

- [ ] 削除済み、期限切れ、返信メッセージはポータル一覧に表示されない。
- [ ] 未読状態と確認状態が職員ごとに独立している。
- [ ] ポータルを表示しただけでは既読にならない。
- [ ] 本文またはスレッドを開いた場合だけ既読になる。
- [ ] 確認必須の連絡で「確認しました」を実行すると確認日時が保存され、再実行しても重複行が作られない。
- [ ] 重要度と未読状態に従って仕様順に並ぶ。
- [ ] 他職員の既読・確認状態を一般職員が参照できない。

### 14.5 回帰

- [ ] 既存の `/calendar`、`/staff-surveys/`、`/staff-rooms/` が従来どおり利用できる。
- [ ] `view_only` 職員が施設データを編集できるようになっていない。
- [ ] 保護者ポータルのログイン、ホーム、お知らせ、アンケートに影響がない。

## 15. テスト観点

### 15.1 自動テスト

| 分類 | 主なケース |
| --- | --- |
| 認証 | 未ログイン、有効職員、無効職員、対応Userなし |
| 日付 | JST日付境界、別タイムゾーン、日またぎ、夏時間のあるタイムゾーン |
| カレンダー | 個人、共有、非表示、アーカイブ、非公開、繰り返し、例外、削除、キャンセル |
| アンケート | 全職員、役割、本人、対象外、未回答、回答済み、期限間近、公開終了 |
| 業務連絡 | 未読、既読、重要、緊急、確認必須、確認済み、期限切れ、削除、返信 |
| 冪等性 | 既読POSTの再送、確認POSTの再送 |
| 件数 | 上限超過、「ほかN件」、`99+` |
| 権限 | 非公開予定の情報漏えい、対象外アンケート直打ち、他職員既読の更新拒否 |

### 15.2 手動確認

- 360px、768px、1280pxの各幅で表示崩れがない。
- 長い予定名、アンケート名、連絡本文、職員名でもカードが横に広がらない。
- キーボード操作とフォーカス順が画面の表示順と一致する。
- 重要度を示す色が見えなくても、ラベルで状態を判断できる。
- 空状態と一部取得失敗時にも、利用者が次にできる操作が分かる。

## 16. 実装順序

1. `/staff/portal`、サイドバー導線、ログイン後遷移を追加する。
2. 既存サービスを利用して今日の予定とアンケートを集約する。
3. `messages` 拡張と `staff_message_reads` を追加し、既存行を通常優先度として移行する。
4. 業務連絡カード、既読POST、確認POST、対象スレッドを開く導線を追加する。
5. 空・障害状態、レスポンシブ、アクセシビリティを調整する。
6. 自動テストと主要画面幅の手動確認を行う。
