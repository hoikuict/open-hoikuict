# 職員の初回設定・再設定案内のQR付き印刷（合意済み仕様）

2026-11-01 JST、版 `STAFF-PRINT-MOCK-001`。ユーザーの「いいね、実装しよう」により、このモックを実装の基準として合意した。[本体の実装・検証記録](staff-auth-print-implementation-2026-11-01.md)あり。同日、実機へ反映済み。[実機配備記録](deployment-staff-auth-print-2026-11-01.md)あり。 [仕様の決定記録 SD-004](spec-decisions.md#sd-004)を参照する。

## 要望と確認済みの範囲

ユーザーの要望は「初回職員登録やパスワード再設定の画面をQRコード付きで印刷できるようにしたい」。確認に対し「本人に渡す個別の案内用紙」を選択した。管理者が職員ごとのコードを発行した後、氏名・コード・有効期限・設定画面のQRを載せたA4用紙を本人へ渡す。

## 今回の解釈・画面案

対象は、職員管理の認証管理から発行する初期設定コードとパスワード再設定コードの表示画面。管理者自身がログインできない場合のメール復旧、共通掲示用QR、保護者登録は今回の対象に含めていない。

- 発行後の画面に「QR付き案内を印刷」を追加する。コードコピーと職員管理へ戻る導線も残す。
- A4縦1枚に、園名、対象職員名、ログインID、6文字のコード、発行日時・有効期限（日本時間）、設定画面のQRと文字のURL、操作手順を印刷する。
- QRは本人用の設定画面のURLだけを含み、コード・ログインID・パスワードを含めない。本人が紙のコードを入力する。初回設定は `/staff/activate`、再設定は `/staff/reset-password`。
- 初回設定はコード確認、ログインID確認・変更、パスワード入力、ログインの順。再設定はコードと新しいパスワードを入力後、既存IDでログインする。用紙の手順を用途別に分ける。
- 管理者の発行理由、他の職員情報、画面メニュー、操作ボタンは印刷しない。パスワードを紙に書かせる欄も設けない。
- コードの有効期間30分・1回限りを維持する。用紙に日時を明記し、期限切れ・紛失は管理者へ再発行を依頼する。

用紙の用途の確認後、モック提示に対する上記の発言で画面・用紙案を合意した。用途の回答だけで画面全体を承認済みとしたものではない。

## 入力・遷移・保存・取消

| 操作・状態 | 提案する動作 |
| --- | --- |
| 初回コード発行前 | 既存のログインID・発行理由を保持。再発行時の既存IDの扱いも本体仕様を維持する |
| 再設定コード発行前 | 既存のログインID・パスワード更新日時の表示、発行理由欄を保持する |
| 発行ボタン | 既存の管理者権限・本人の有効状態・入力検証を行い、成功したときだけ既存の発行処理で保存する |
| 印刷ボタン | 現在表示している案内を印刷。追加発行、期限の延長、DB更新、メール送信をしない |
| 印刷をキャンセル | 同じ案内に戻る。発行済みのコードと期限を保持する |
| 画面を離れる | 同じコードは再表示できない旨を示す。モックでは確認ダイアログで取消可能 |
| 期限切れ | 期限切れ表示と再発行の案内。印刷ボタンを無効にする。本人画面は既存の期限検証を維持 |
| URL未設定 | QRや印刷を利用できない理由を表示。本体ではコード発行前に設定を検証する案 |
| 入力・発行エラー | エラーを表示し、入力内容を保持する。印刷対象のコードは新規表示しない |

紙を印刷しても再発行や利用によりコードが無効になる場合がある。印刷済みかどうかを認証や期限の判定に使わない。

## モックの場所・確認方法

保存先は `tools/staff-auth-print-preview/index.html`。同じフォルダーのCSS・JavaScriptとともにブラウザーで開く。今回の確認用サーバーは `http://127.0.0.1:8898/`。本番アプリの起動・DB接続は不要。

1. 上部の「用途」で初回設定・パスワード再設定を切り替え、発行後の用紙を確認する。
2. 「QR付き案内を印刷」で印刷プレビューを確認する。白黒・背景色なしでもコードとQRを読める構成。
3. 「画面」を「管理者・コード発行」に変え、「状態」で未入力・一部入力・入力済み・エラーを試す。既存の入力項目を省略していない。
4. 「QRの先の画面を試す」で本人の入力画面へ進む。初回設定は `H7K3MP`、再設定は `R9T4NW` の架空コードを使う。
5. 用紙の期限切れ・施設URL未設定も「状態」で確認できる。見本の時刻は2026-11-01 10:00に固定。

QRのURLは `example.invalid` の架空URLであり、スマートフォンで読み取っても実際の登録には接続できない。「QRの先の画面を試す」はモック内の表示切替である。設定内容をブラウザーの永続ストレージにも保存しない。

印刷見本：`output/pdf/staff-activate-handout-preview.pdf` と `output/pdf/staff-reset-handout-preview.pdf`。どちらも架空データのA4・1ページ。

## 合意後の実装で確認すること

施設URLは既存の管理設定から取得し、リクエストのHostを無条件に印刷URLに使わない。URL未設定時は発行前の検証、既存のコード発行処理との境界を確認する。発行日時・有効期限は保存したトークンの実値を使い、印刷時に現在時刻から計算し直さない。

管理者限定、CSRF、`Cache-Control: no-store`、ワンタイムコードの再表示不可、失効済みコードの拒否などを維持する。QRは既存のqrcodeライブラリーで施設内生成し、外部QR生成サービスへ送信しない。長い園名・職員名・ログインID・施設URLでも読める折返しと印刷枚数を実装時に検証する。

合意済み：このモックの用紙レイアウト・文言・QRにコードを含めず手入力する操作。後続の実機配備は同日完了。プリンター実機・スマートフォン実機の確認は未実施。上の「確認基準・検証結果」はモック作成時点の履歴であり、本体の変更結果は実装記録を参照する。
