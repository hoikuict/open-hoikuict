# UI変更の確認とモック試用

画面の位置・大きさ・表示条件・操作順の認識を合わせるため、UIの変更は「仕様確認 → 操作できるモック → 実装」の順で進める。2026年9月18日にユーザーが希望した進め方を記録する。

## 仕様の確認

変更書に書かれた要望と、補足の提案・未確定事項を区別する。対象画面、入力項目、表示条件、ボタンを押した後の遷移、保存のタイミング、修正・取消・エラー時の動作を短く整理する。

迷う点は、文章の質問だけでなく、モックの選択肢として比較できるようにする。回答前の初期表示は仮案であり、確定仕様とは扱わない。

## モックを試す

本番の画面構成を参考に、架空データで押して試せる画面を用意する。配置だけでなく、入力・確認・修正・取消・完了までを再現する。未入力・入力済み・一部入力・入力エラーなど、表示が変わる条件も用意する。

変更対象の画面にある既存の入力項目を省略せず、変更後の入力順と画面全体の長さも確認できるようにする。日次連絡では、睡眠・食事などの既存項目と追加するお迎え予定を一緒に試す。

確認用の画面切替やサンプルの状態表示は、本番の画面に追加する機能とは区別する。モックから本番への保存、メール・プッシュ送信、打刻は行わない。

ユーザーがモックを試し、画面と操作の認識を合わせる。修正があればモックを更新して再確認し、合意した版を実装の基準にする。

## 実装と配備

実装依頼を受けてから、合意した画面と動作をアプリに反映する。モックで見えない権限・競合・履歴・日付制約などは実装側で検証する。モックだけで、それらの動作確認まで済んだとは扱わない。

配備依頼を受けた場合は、既存の本番機能を保持する版を固定し、バックアップ・移行検証・反映・稼働確認を行う。
