# 初期台帳Excelの試用案（2026-09-22）

状態：以下は仕様確認時のモック案。ユーザーの本実装依頼を受け、現在はローカルアプリへ実装済み。実装内容と検証は [実装記録](initial-ledger-import-implementation-2026-09-22.md) を参照。本番・新PCへの配備は未実施。

## ユーザーの要望・合意済み事項

- 既存のExcel台帳から該当列をコピーして初期登録を準備したい。
- 園児1人につき1行。保護者①②も同じ行に入力する。
- 初期取り込みは台帳だけ。保護者アカウントは後から作る。
- 園児整理番号・家庭整理番号・家庭名は初回に自動設定し、手入力を求めない。家庭名は基本を姓とし、重複する場合は姓名にする。
- 既存環境の保護者ID 4への98人の明示的な紐づけは配信確認用で、維持する。今回の初期登録テンプレートの対象には含めない。

## 今回具体化した案

Excelは「入力用」「記入例」「項目の説明」の3シート。入力用は200行、38列。見出しは4行目、入力開始は5行目。3つの自動設定項目はExcelの入力列から外した。電話番号は文字列、日付は日付型。列の対応を保って値のみ貼り付ける。記入例は架空の3園児・2家庭で、きょうだいと同姓の別家庭を含む。

| 区分 | 含む項目 |
| --- | --- |
| 園児と所属 | きょうだいグループ（任意・指定方法は未合意）、クラス名、クラス表示順、姓名・姓名カナ、生年月日、入園日、在園状態、性別、退園日 |
| 住所と連絡先 | 家庭住所・電話番号、園児固有の住所・電話番号 |
| 保護者①② | 各10項目：姓名、姓名カナ、続柄、メール、電話、勤務先、勤務先住所、勤務先電話 |
| 任意の照合情報 | 照合用氏名、照合用氏名種別 |

現行CSVの業務入力項目を保持し、3つの手入力項目を確認画面の自動設定表示へ変更する案。職員、保護者アカウント、閲覧権限はこの入力の対象外。

番号はモック内で園児C001、家庭F001のように自動採番する。画面で氏名を修正しても園児番号を変更しない。表示名の重複を家庭統合の根拠にはしない。

きょうだいの指定方法は質問中のため仮案。任意の「きょうだいグループ」に同じ文字を入れた行だけを同じ家庭にまとめ、空欄は園児ごとに別家庭とする。姓、住所、電話番号だけではまとめない。

家庭名は、その家庭の先頭行の園児の姓を使う。同姓の別家庭が入力内にある場合は、それぞれ先頭行の園児の姓名にする。姓名まで重なる別家庭は後の家庭に自動家庭番号を添える。例：見本 → 見本 花／見本 光 → 見本 花／見本 花（F002）。誰の姓名を基準にするかと、重複時の補足表示は試用案である。

入力内容が完全に同じ行はエラー。同じカナ・生年月日でも他の項目が異なる場合は原本確認の警告を出し、自動で人物を統合しない。

同じ家庭の複数行では、空欄を他の行の明示入力で補う。同じ項目に複数の値がある場合は行番号・列名を示して停止する。保護者のいずれかの項目を入力する行は、姓・名の両方を求める。電話番号がExcel内で数値だった場合は、先頭の0の原本確認を求め、自動で0を付けない。

## 試用画面の流れ

1. Excel取得、ファイル選択、シート選択。「入力用」を初期選択し、架空の「記入例」も試用できる。
2. 未入力・入力済み・一部入力・エラーありの4状態を切り替える。
3. 園児・家庭・クラス数、エラー・警告を表示する。自動設定3項目は読取専用で表示し、入力38項目を編集できる。
4. 自動設定した家庭整理番号・家庭名、所属園児、保護者①②を表で照合する。
5. エラーなし・データありで最終確認へ進む。確認チェック後に「登録を試す（モック）」を押す。
6. モックの登録はブラウザーのメモリーだけ。同じ内容を同じページで再読込した場合は同じ採番を使う。別内容は別の採番枠として扱い、行番号が同じことを根拠に既存園児を更新しない。閉じると消える。

修正に戻ると入力を保持する。編集・再読込を行うと以前の確認を無効化する。取り消すと今回の読込内容を消し、元Excelは変更しない。エラーのある状態では登録へ進めない。実際のアカウント作成、招待送信、外部通信、DB更新、配信テストの権限変更は行わない。

## 本実装前に確認する事項

- きょうだいの指定を任意のExcel列にするか、読込後の画面で選ぶか。
- 家庭名は先頭行の園児の姓名を基準にする使い方でよいか。保護者名を使う必要があるか。
- 横に長い38列と、画面側の入力順が実務に合うか。
- 同じ家庭の空欄補完と、同名の別家庭の表示方法。
- 自動採番は初回取り込み用。登録後に変更したExcelの再取り込みと既存台帳の照合は別途設計が必要。単なる行位置や氏名を人物の固定IDとせず、初期取込セットと採番の永続的な対応を検討する。
- 必要に応じ、保護者③以降、健康情報・追加緊急連絡先を別の入力として扱うか。これらは現行CSVの対象外で、本案でも未対応。

本実装では、事前検証に書込みを伴わせず、確定時にファイル・台帳の変更を再確認し、クラス・家庭・園児・保護者プロフィールを1トランザクションで保存する必要がある。再取込で重複させず、既存データの削除や他家庭への移動を推測しない。

既存5CSVの移行は継続中。クラス6件・家庭82件・園児100件の変換と隔離検証は完了。旧家庭ID 1・3・152の情報が未収録。保護者アカウント8件、明示リンク105件を維持したまま、足りない家庭情報と家庭をまたぐリンクの取り込み経路を準備する必要がある。初期テンプレートの試用でこれらを置き換えない。
