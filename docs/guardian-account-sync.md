# 家族プロフィール・保護者アカウントの共通入力と入園時の招待

## 2つの登録ルートを併用する

| 状況 | 園の操作 | 保護者の操作 |
| --- | --- | --- |
| これから入園し、台帳情報がない | 子どもの名前と保護者メールだけで「初回入力を依頼」 | 初期情報を入力・提出し、園の承認後に利用を開始 |
| 既存台帳に保護者情報がある | 園児詳細の対象者から「この保護者のアカウントを登録」。入力済み項目を引き継ぎ、メール・対象園児を確認 | 招待で本人確認とパスワード設定を行い、登録済み情報を利用 |
| 既存園児の情報を保護者に補ってもらう | 園児詳細で対象者を選び「この保護者に初回入力を依頼」 | 自分の情報を提出。園の承認時に指定した保護者へ反映 |

どの入口でも同じ家族台帳を使用する。別の保護者や兄弟姉妹を新しく作り直す必要はない。
既存園児への初回入力依頼では、招待先へ台帳の個人情報を先に開示せず、提出内容を園が確認する。
既にアカウントがある人は、そのアカウントの認証管理を使う。

### 保存時に保持する情報

- 保護者②だけの登録は②のまま表示・保存する。①へ移し替えない。
- 家族・園児編集画面に表示していない3人目以降と、編集対象外の追加情報を保持する。
- 氏名欄が空の保護者枠は削除指示として扱わない。記載のない人を一覧から消さない。
- 既存園児への初回入力では、指定した本人以外の情報を保持する。勤務先・自宅電話・健康情報など任意項目が空欄の場合も、既存の値を保持する。削除が必要な場合は園が確認して訂正する。
- 初回入力で提出された園児のカナ・生年月日・入園日・健康情報も、園の承認後に台帳へ反映する。既存データに変更があった場合は承認を止め、再確認する。
- 園の編集画面で、氏名が入力済みの保護者の電話・勤務先などを明示的に空欄にして保存すれば、その項目の訂正はできる。
- 家族の所属と保護者の閲覧権限は別に管理する。初回登録の承認では選んだ園児だけを許可する。

従来の家庭CSV（4列）を取り込んだ後の家族編集でも、登録済みの保護者情報を保持する。
家庭CSVは保護者①②の20列を追加した24列に対応する。既存の4列CSVも利用できる。
CSVの空欄は登録済みの値を保持し、保護者を更新するときは同じ行に本人の姓・名を指定する。
詳しい取り込み順序と確認方法は [家庭・園児CSVの取り込み](family-guardian-csv-guide.md) を参照する。

## 入園時：園の初期入力は2項目だけ

1. 管理者が園児一覧または保護者アカウント一覧の「保護者に初回入力を依頼」を開く。
2. **子どもの名前・保護者のメールアドレスだけ**を入力し、「初回入力の招待を送信」を押す。
3. 保護者はメールのリンクから、子どものカナ・生年月日・入園予定日、保護者氏名・カナ・続柄、住所・電話・勤務先などを一度入力して提出する。メールアドレスは招待先を使用し、再入力は不要。
4. 管理者がホームの「すべての承認待ち」にある「保護者の初回登録」から提出内容を開き、招待先と保護者・園児の対応を確認する。確認欄にチェックし、確認理由を記録して承認する。保護者アカウント一覧の「確認待ちの初回登録」、対象者の認証管理の「登録申請の履歴」からも確認できる。
5. 承認時に園児・家族プロフィール・保護者アカウントへ反映し、対象園児だけの閲覧を許可する。
6. 保護者は2通目のメールからパスワードを設定して利用開始する。ログイン後に初期情報を入力し直す必要はない。

園で保護者氏名・カナ・生年月日を事前登録する必要はない。これらは保護者の提出内容を園が確認する。
未登録の園児は承認時に台帳へ作成する。生年月日などの仮データは作らない。
承認前の招待・入力画面では、既存の家族情報や園児情報は公開しない。
「初回入力を受け付けました」は申請を保存した後に表示する。提出時点では園への通知メールは送らず、管理者ホームの承認待ち件数・一覧へ表示する（開いているホームは「更新」で取得）。承認・却下・取消後は承認待ちから外れる。承認前の申請は家族台帳や通常の「プロフィール変更申請」には表示しない。
招待リンクは24時間、リンクを開いた後の入力画面は2時間有効。期限切れや差し戻し後は、認証管理から再送する。

Cloudflareの認証後などにリンクから進めない場合、初回登録画面の「登録コードまたはメールのリンク」へ、同じメールの登録コードを貼り付けて続ける。
古い案内メールに登録コードの記載がない場合は、メール本文の元のリンクをコピーして貼り付ける。
園の承認後のパスワード設定メールも同じ操作に対応する。登録コードはCloudflareの認証コードとは別で、元のリンクと共通の24時間・1回限りの認証情報。
再送後は最新のメールを使う。ブラウザーのアドレス欄からコピーしたURLには登録情報が残っていないため、メール本文からコピーする。

## 園児が既に登録されている場合

園児詳細の家族プロフィールで、対象者の「この保護者に初回入力を依頼」を開く。
子どもの名前は設定済みなので、園はメールアドレスだけ入力する。
保護者未登録の場合は同じ場所の「保護者に初回入力を依頼」を使う。

承認時に既存園児と指定した保護者へ反映し、同じ家族の他の保護者の情報は保持する。
家族の住所などの共通項目はきょうだいにも反映するが、きょうだいの閲覧権限は付けない。
招待後に園児・家族情報や紐付け先が変わった場合は、上書きを避けるため承認を止める。最新情報を確認して再招待する。

## 登録済みの情報を活用する場合

既存の「この保護者のアカウントを登録」では、台帳の入力済み項目を引き継げる。
既存アカウントは編集画面で「家族プロフィールの保護者と紐付ける」を設定する。
通常の本人情報照合による招待も従来どおり利用できるが、入園時の2項目だけの招待には上の「初回入力を依頼」を使う。
利用開始後のプロフィール変更は、保護者の「登録情報」から申請し、園が「プロフィール変更申請」で承認する。

## 反映される項目

| 項目 | 動作 |
| --- | --- |
| 保護者氏名 | 家族の姓・名とアカウント表示名を同期。アカウントで編集する際は姓と名をスペースで区切る |
| メール・電話・勤務先名・勤務先住所・勤務先電話 | 明示的に紐付けた保護者について双方向に同期 |
| 自宅住所 | 家族と同じ住所を使っているアカウントは共通更新。既に異なる住所を持つアカウントは保持 |
| カナ・照合用氏名 | 初回登録フォームへカナを引き継ぐ。照合用の表記は園が確認して保存する |
| 続柄・自宅電話など | 家族台帳で管理し、同じ家族の園児に反映 |
| ログインID・パスワード・認証状態 | 共通項目の編集では変更しない。利用開始後のログインID変更は既存の管理者本人確認手続きを使う |

連絡先メールを変更すると、旧宛先の進行中の登録申請と、まだ送信待ちの案内を取り消す。
既に送信処理中・送信済みのメールを回収することはできないが、旧登録リンクは無効になる。
既存の職員管理による家族・保護者の紐付けは、保護者が以前送った申請によって書き換えない。

## メールの動作確認

認証管理の「初回設定コードを発行してメール送信」「再設定コードを発行してメール送信」では、本人確認の理由を記録し、コード発行と同時に登録メールアドレスへの送信を受け付ける。
案内にはコード入力URL、6文字のコード、有効期限（24時間）、設定後のログインURL・ログインIDを含む。コードはパスワードではなく、案内先の画面でパスワードを設定するために使う。
24時間の期限は変更後に発行した保護者向けコードに適用する。発行済みのコードはメールに記載された元の期限が有効で、期限切れの場合は発行し直す。
初回入力の未承認状態ではコードを発行できない。承認後の通常のパスワード設定案内は従来どおり自動送信する。
再発行は60秒以上あけ、1日10回まで。発行し直すと以前のコードと送信待ちメールを取り消す。期限切れ、使用済み、取消済み、宛先変更後のコードは配送しない。

認証管理の「メールの配送状況」で直近20件の宛先・受付日時・状態を確認する。
送信待ち、処理中、メールサーバー受付済み、送信失敗、送信取消を区別する。本文や登録トークンはこの画面に表示しない。
メールサーバー受付済みは本人の受信箱への到着確認とは別。受信箱でも確認する。

TrueNASの初期実機検証では、SMTPはMailpitのテスト受信箱へ配送する構成。外部の保護者へは届かない。
Gmailなどの外部SMTPへ切り替えた環境では、実際の招待先へ届くため、以下のMailpitの手順は使わず本人の受信箱で確認する。
PCの別端末で次を実行し、端末を開いたまま `http://127.0.0.1:18125` を開く。

```bash
ssh -N -L 18125:127.0.0.1:18125 <TrueNASのSSH接続先>
```

テスト用アカウントで招待を送信し、受信箱の1通目・園の承認後の2通目を確認する。
実機のCloudflare Accessは許可したメールだけが通れる構成なので、試験に使う本人のAccessアカウントも許可対象に含める。
実在の保護者への導入には、外部SMTPサービス・送信元と、保護者が到達できるAccess設定の準備が必要。
