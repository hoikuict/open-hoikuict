# 家族プロフィール・保護者アカウントの共通入力と入園時の招待

## 入園時：園の初期入力は2項目だけ

1. 管理者が園児一覧または保護者アカウント一覧の「保護者に初回入力を依頼」を開く。
2. **子どもの名前・保護者のメールアドレスだけ**を入力し、「初回入力の招待を送信」を押す。
3. 保護者はメールのリンクから、子どものカナ・生年月日・入園予定日、保護者氏名・カナ・続柄、住所・電話・勤務先などを一度入力して提出する。メールアドレスは招待先を使用し、再入力は不要。
4. 園が認証管理の「登録申請の履歴」で提出内容を読み、招待先と保護者・園児の対応を確認する。確認欄にチェックし、確認理由を記録して承認する。
5. 承認時に園児・家族プロフィール・保護者アカウントへ反映し、対象園児だけの閲覧を許可する。
6. 保護者は2通目のメールからパスワードを設定して利用開始する。ログイン後に初期情報を入力し直す必要はない。

園で保護者氏名・カナ・生年月日を事前登録する必要はない。これらは保護者の提出内容を園が確認する。
未登録の園児は承認時に台帳へ作成する。生年月日などの仮データは作らない。
承認前の招待・入力画面では、既存の家族情報や園児情報は公開しない。
招待リンクは24時間、リンクを開いた後の入力画面は2時間有効。期限切れや差し戻し後は、認証管理から再送する。

## 園児が既に登録されている場合

園児詳細の家族プロフィールで、対象者の「この保護者に初回入力を依頼」を開く。
子どもの名前は設定済みなので、園はメールアドレスだけ入力する。
保護者未登録の場合は同じ場所の「保護者に初回入力を依頼」を使う。

承認時に既存園児と指定した保護者へ反映し、同じ家族の他の保護者の情報は保持する。
家族の住所などの共通項目はきょうだいにも反映するが、きょうだいの閲覧権限は付けない。
招待後に園児・家族情報や紐付け先が変わった場合は、上書きを避けるため承認を止める。最新情報を確認して再招待する。

## 登録済みの情報を活用する場合

既存の「この保護者のアカウントを登録」では、台帳の入力済み項目を引き継げる。
既存アカウントは編集画面で「家族プロフィールの保護者と紐付ける」を設定する。
通常の本人情報照合による招待も従来どおり利用できるが、入園時の2項目だけの招待には上の「初回入力を依頼」を使う。
利用開始後のプロフィール変更は、保護者の「登録情報」から申請し、園が「プロフィール変更申請」で承認する。

## 反映される項目

| 項目 | 動作 |
| --- | --- |
| 保護者氏名 | 家族の姓・名とアカウント表示名を同期。アカウントで編集する際は姓と名をスペースで区切る |
| メール・電話・勤務先名・勤務先住所・勤務先電話 | 明示的に紐付けた保護者について双方向に同期 |
| 自宅住所 | 家族と同じ住所を使っているアカウントは共通更新。既に異なる住所を持つアカウントは保持 |
| カナ・照合用氏名 | 初回登録フォームへカナを引き継ぐ。照合用の表記は園が確認して保存する |
| 続柄・自宅電話など | 家族台帳で管理し、同じ家族の園児に反映 |
| ログインID・パスワード・認証状態 | 共通項目の編集では変更しない。利用開始後のログインID変更は既存の管理者本人確認手続きを使う |

連絡先メールを変更すると、旧宛先の進行中の登録申請と、まだ送信待ちの案内を取り消す。
既に送信処理中・送信済みのメールを回収することはできないが、旧登録リンクは無効になる。
既存の職員管理による家族・保護者の紐付けは、保護者が以前送った申請によって書き換えない。

## メールの動作確認

認証管理の「メールの配送状況」で直近20件の宛先・受付日時・状態を確認する。
送信待ち、処理中、メールサーバー受付済み、送信失敗、送信取消を区別する。本文や登録トークンはこの画面に表示しない。
メールサーバー受付済みは本人の受信箱への到着確認とは別。受信箱でも確認する。

TrueNASの初期実機検証では、SMTPはMailpitのテスト受信箱へ配送する構成。外部の保護者へは届かない。
PCの別端末で次を実行し、端末を開いたまま `http://127.0.0.1:18125` を開く。

```bash
ssh -N -L 18125:127.0.0.1:18125 <TrueNASのSSH接続先>
```

テスト用アカウントで招待を送信し、受信箱の1通目・園の承認後の2通目を確認する。
実機のCloudflare Accessは許可したメールだけが通れる構成なので、試験に使う本人のAccessアカウントも許可対象に含める。
実在の保護者への導入には、外部SMTPサービス・送信元と、保護者が到達できるAccess設定の準備が必要。
