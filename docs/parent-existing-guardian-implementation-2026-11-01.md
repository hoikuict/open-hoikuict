# 在園児の保護者追加・招待の入力範囲の修正

2026-11-01 JST。[SD-005](spec-decisions.md#sd-005)で、ユーザーが[モック](parent-existing-guardian-proposal-2026-11-01.md)を確認し「両方に適用して実装」を選択したことに基づく実装。同日、ユーザーの依頼により実機へ反映済み。[実機配備記録](deployment-parent-guardian-2026-11-01.md)を参照。以下の検証欄は実装時点の結果。

## 変更した動作

「この保護者を招待」「新しい保護者を追加」の両方で、在園児への招待先を「保護者アカウントの登録」に変更した。対象園児は氏名の確認だけとし、保護者本人の姓・名・カナ2欄・続柄・電話を必須、勤務先・勤務先住所・勤務先電話を任意とする。19項目・必須13項目から9項目・必須6項目になった。

園児の氏名・カナ・生年月日・入園予定日、自宅住所・電話、健康情報、2人目の保護者は入力・更新対象にしない。新入園と共通QRからの申請は従来の入力を維持する。

画面を隠すだけでなく、提出時の検証と承認時の更新も本人情報だけに限定した。保護者のPOSTで園児ID・保護者枠・入力範囲を指定しても採用せず、招待に保存された対象を使用する。余分な園児項目・家族項目・別保護者の項目は申請に保存しない。

本人情報は園の承認後に反映し、選んだ園児だけの閲覧権限を付ける。園児プロフィールを再検証・書換えする処理を通さず、氏名・日付・健康情報・照合用氏名を保持する。本人以外のプロフィール、既存の任意の勤務先情報、家族共通の住所・電話、きょうだいの閲覧権限も保持する。

招待メールと管理者の招待説明を本人情報の入力に合わせ、承認画面では今回提出された9項目を表示する。確認理由・確認済みチェック・承認・却下の操作は維持する。

## 互換性と操作

- **発行済み・未提出の招待**：対象園児が決まっている個別招待は、更新後の画面から本人9項目で提出できる。再招待は不要。古い画面から余分な項目が送られても本人情報だけを保存する。
- **提出済みの旧形式申請**：既存の提出内容を変更しない。承認画面に旧形式と明示し、提出時の入力範囲と既存の承認処理を維持する。新しい申請を旧形式に読み替えないため、サーバーが保存時に `submitted_data._input_scope = guardian_only_v1` を記録する。クライアントからこの値を受け付けない。
- **新入園・共通QR**：既存の画面・必須項目・確認方法を維持。新入園の個別招待は28項目、必須13項目。保護者POSTによる本人限定形式への切替はできない。
- **園児詳細からの初回入力依頼**：同じ在園児向け個別招待なので、本人情報の登録に限定する。園児・自宅・健康情報の補完や訂正は、従来の園児編集・承認付きプロフィール変更申請を使う。既に提出済みの補完申請は上記の旧形式として残る。
- **エラーと取消**：入力エラーは本人の入力を保持する。「入力をやめる」で確認を表示し、取消なら入力を保持、終了なら入力欄を画面から除去する。終了はHTTP通信・DB更新・招待取消をしない。JavaScript無効時には取消ボタンを表示せず、通常のフォーム送信は利用できる。
- **期限・再送**：招待24時間、入力画面2時間、提出1回、再送による旧招待・入力セッションの失効を維持する。
- DBスキーマ変更、既存申請の一括更新、依存パッケージ追加はない。
