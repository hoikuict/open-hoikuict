# 日常運用と障害対応

運用担当者は、アカウント、保存先、配送、端末、バックアップ、更新版を確認できるようにします。open-hoikuictは無保証のオープンソースであり、施設・法人が利用範囲、個人情報の扱い、問い合わせと障害時対応を決めます。

## 毎日の確認

| タイミング | 確認すること | 問題がある場合 |
| --- | --- | --- |
| 開園前 | 施設URL、職員ログイン、キオスクの起動 | 接続・認証・端末設定を確認し、紙の打刻へ切り替える |
| 朝 | 日次連絡、出欠、打刻、不整合アラート | 園児ごとに確認し、必要に応じて保護者へ連絡 |
| 日中 | ホームの承認待ち、端末警告、メール・通知の失敗 | 登録申請の処理、端末の再起動・接続確認、代替連絡 |
| 降園後 | 未降園・未打刻、お迎え予定、記録漏れ | 理由と履歴を残して訂正 |
| 定期バックアップ後 | 最終成功時刻、検証結果、worker稼働、別系統コピー | 失敗の原因を確認し、復旧可能な世代を確保 |

職員の業務操作は[日々の業務](daily-work.md)、通知の条件は[通知ガイド](notifications.md)を参照してください。

## キオスク端末を監視する

管理者は `/settings/guardian-terminals` で端末名、監視時間、有効・無効を設定します。署名付き端末識別子で約30秒ごとの応答を保存し、監視時間内に2分を超えて応答がないと管理者ホームへ警告します。初期の監視時間は日本時間7〜19時です。

無応答だけではネットワーク断・スリープ・画面を閉じた状態を区別できません。現物の電源・接続・アプリ表示を確認してください。一般のChromebookの専用画面はOS全体を操作不能にする機能ではありません。[端末設定ガイド](chromebook-guardian-kiosk.md)も確認します。

## バックアップと復元

管理者は `/settings/backups` から即時実行を依頼し、毎日・毎週のJST基準スケジュールと履歴を確認できます。実際の作成には別プロセスの `scripts.backup_worker` が必要です。TrueNAS基本構成のworkerは `backup-ui-trial` プロファイルにあり、通常起動だけでは動作しません。

同じ日の予定時刻を過ぎてworkerを起動した場合は1回実行しますが、過去日・過去週の取りこぼしは持ち越しません。同じ予定枠の失敗は自動再試行されないため、原因を確認してから再実行を依頼します。画面に予定があることと、バックアップ成功は別に確認します。

画面の「作成完了」と、[取得・検査・別系統保存・復元試験の4段階](backup-restore-spec.md#verification-stages)を分けて確認します。形式2では全添付・写真参照・必須テーブル・主要件数も検査します。複製・復元試験の証跡は別途必要です。[確認手順](backup-verification-guide.md)と[現在の実装・実機確認範囲](backup-restore-spec.md#implementation-status)に従います。

園児・保護者の写真と園児の性別は主DBに保存され、バックアップに含まれます。添付は `storage/document_reviews/` の確認依頼ファイルを含む全種類が対象です。形式2は定期実行設定も保存します。旧形式1は追加検査・設定再準備を要します。復元先では定期実行を無効にし、古い実行依頼を再投入せず、担当者が保存先・時刻等を確認してから再開します。

正式な停止方式、施設文例DB・設定・秘密情報の保護、別系統複製、保持、復元は[バックアップ仕様](backup-restore-spec.md)と[運用試験仕様](pilot-deployment-spec-v2.md)に従います。

## アカウントの管理

初期管理者はローカル認証CLIで作成し、本人が有効化コードからパスワードを設定します。管理者は職員の基本ロール・業務別権限・担当クラス、保護者の状態・園児リンクを確認します。

退職・異動・退園時の停止担当と実施日を決め、連絡先変更時には招待・再設定の配送状況も確認します。具体的な操作は[アカウントガイド](accounts.md)にまとめています。

## 更新する前後

1. 現在と更新先のコミット、イメージ、Compose構成、DB・添付の保存先を記録します。
2. [変更履歴](history.md)で追加テーブル、権限、通知、初期値の変更を確認します。
3. 隔離したDBコピーで起動・スキーマ更新を確認し、復旧に使えるバックアップを取得します。
4. [TrueNAS更新手順](truenas-beginner-installation-guide.md#maintenance)に沿って反映します。
5. ヘルスチェック、ログイン、既存データ、キオスク、配送、バックアップ状態を確認します。

`/healthz` はHTTPの生存確認で、SMTP配送や端末表示、復元可能性まで保証しません。実際の利用者へ送信する操作は検証のために無条件に実行しません。

## 障害時の代替手段

| 業務 | 代替手段 | 復旧後 |
| --- | --- | --- |
| 登降園 | 紙の登降園簿 | 入力者・日時・理由を残して反映 |
| 保護者への確認 | 電話など園が指定する連絡手段 | 対応結果と未処理分を確認 |
| 体調・服薬の申し送り | 紙の記録と職員間の引き継ぎ | 必要な記録を整理して反映 |
| ログイン不能 | 管理者・運用担当者の復旧手順 | 対象アカウントの再設定・有効状態を確認 |

復元中は利用を停止し、通知が誤配送されない隔離条件を守ります。障害の連絡先、対応可能な時間、判断する責任者、紙記録の保管場所を園内で共有してください。
