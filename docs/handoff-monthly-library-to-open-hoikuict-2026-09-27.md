## ユーザーが指定した内容

- 空白の帳票を表示し、候補の文章を選択すると選択中のセルへ反映する。
- Google Driveの帳票の実物に様式を合わせる。原本の見出し・行・列・縦横を維持する。
- 0・1・2歳児クラスは個人別、3歳児以上は集団の様式。年齢は年齢クラスで判断する。
- 「この欄に追記」ボタンは不要。候補の選択だけで反映する。削除はBackspace/Delete等、修正はセル内で自由に行う。
- 食育は4分割せず1つの枠。
- 候補一覧にキーワード検索。
- 原文を出典付きで選ぶ操作と、AI提案を選ぶ操作を切り替える。
- 個人計画は既存操作を残し、過去3か月程度の計画と反省を確認しながら入力できるようにする。
- 履歴を加える際も「縦横変えないで」。過去・今月とも、横は「生活・健康／あそび／環境構成・援助活動／評価・反省」。過去の月を行として並べ、今月の列位置に揃える。
- 文例の参照元として `C:/python/getsuan-rag/getsuan.sqlite` を指定し、使えるか確認を求めた。読み取り専用で調査済み、利用可能。実際の画面への接続は未実施。

## 操作見本の現在の動作

- 対象月は2026年10月の固定見本。0〜5歳の様式を切り替えられる。園児・文例・AI提案・過去の履歴はすべて架空データ。
- 0〜2歳の上段はクラス共通のねらい・家庭との連携・評価反省など。下段は園児別の4列。原本の行ブロックに合わせてページを切り替える。
- 各本文セルはtextarea。候補を選ぶと手入力を残して末尾へ改行と `○` 付きで追記し、セルへカーソルを戻す。同じ候補本文の重複反映を防ぎ、削除後は再選択できる。
- 検索は見本内の候補本文に対する絞り込み。全角半角を正規化し、空白区切りで全語一致。空欄で全件、0件ならその旨を表示する。
- 「過去3か月を表示」を開くと選択園児の7〜9月を表で表示し、その下の同じ列構成で10月を入力する。表示中は選択園児の行に絞り、閉じると従来の一覧へ戻る。入力は保持する。
- 履歴は閲覧専用。全月の計画3項目と個人全体の反省を表示する。セル選択では対応列の強調だけを変え、過去の文章や列順は変えない。記録のない月は明示し、別の園児や別月で埋めない。
- 小さい画面も帳票の縦横を維持し、帳票内だけ横スクロールする。スマートフォン向けに4項目を縦積みに変換しない。
- 3〜5歳は養護・教育の領域×4列、食育1枠、評価反省、右側の行事表。食育の旧4欄の見本下書きがある場合は本文と出典を1欄へまとめる。
- 出典は折りたたみ表示。取り消しと画面内の保存・復元を持つ。これは本体DBへの保存ではない。

候補へ付ける `○`、履歴表示中に選択園児だけを表示すること、欠損月の表現などは今回の見本で具体化した実装判断。ユーザーの明示要望と区別して扱う。保存タイミング、他の月への移動、履歴の参照版、長文の印刷など、本体への統合で追加の設計が必要な部分は残っている。

`C:/python/getsuan-rag/getsuan.sqlite` を SQLite の `mode=ro` と `PRAGMA query_only=ON` で調べた。取り込みや更新はしていない。

| 内容 | 確認結果 |
| --- | --- |
| 文例数 | 128,008件、正規化本文の重複を除くと60,668件 |
| 条件 | 年齢0〜5歳、月1〜12月、年、項目、個人／共通等の区分、領域 |
| 本文と出典 | `phrase` → `cell` / `source`。欠損参照0件 |
| 検索 | `phrase_fts` のtrigram索引と短い語の部分一致を確認 |
| 元資料 | 成功1,488件、別に取り込みエラー8件 |
| 1歳児・10月・個人別 | 生活健康689件、あそび528件、環境援助474件、反省157件（重複なし） |

参考コードは `C:/python/getsuan-rag/app.py` の `FORMS` と `/api/search`、`build.html` のセル編集・候補反映。参照先プロジェクトのファイルは変更していない。既存の検索サーバーをそのまま本番起動することは前提にしない。

検索条件の重要な対応：

- 個人4欄は必ず `section=個人別`。画面の「環境構成・援助活動」は `item=環境構成・援助`。
- クラス共通は `section=クラス全体`。同じ「評価・反省」でも個人別と混ぜない。
- 幼児4列は `ねらい`／`環境構成`／`予想される子どもの姿`／`援助・配慮` に対応し、区分と領域も指定する。
- 食育1枠は `(section=食育 OR item=食育)` を年齢・月と組み合わせて検索する。`item=食育` だけでは領域表から取り込まれた食育が抜ける。
- 選択後も本文・原文/AIの種別・参照した文例ID・出典を保持する。ファイルパスだけをDriveファイルIDや確定セル座標とみなさない。

**このDBを同じ園児の過去3か月の履歴として使わない。** 園児の安定した識別IDがなく、`age_label` は月齢表記。個人履歴は本体の `child_ref` 等、月次文書、実施後の評価反省、版・権限に紐づける必要がある。

## 未実装と本体側で必要な作業

現在あるのは仕様、操作見本、DBの利用可否調査。`hoiku-plan-docs` のアプリ本体にはこの新画面を組み込んでいない。open-hoikuictへの本実装・配備、実DBの文例候補表示、AI生成、実園児の履歴取得、サーバー保存、印刷出力は未実装。

次に本実装へ進む場合の順序：

1. 本体の最新作業状態・配備記録・計画機能を確認する。既存の未コミット変更が多数あるので、今回の資料以外を上書き・取り消ししない。
2. 元の帳票構造を保持できる保存契約を設計する。帳票ID/版、年齢クラス、園・クラス・年月、`child_ref`、領域・列のフィールドID、本文と出典を分けて保持する。既存月案10項目へ機械的に押し込まない。
3. 本体の園・職員・クラスの権限を使い、指定SQLiteを読み取り専用で検索するアダプターを追加する。環境ごとにパスを設定し、Windowsの絶対パスを本番コードに固定しない。DBをGitに含めない。
4. 合意済みの空白帳票・直接編集・候補検索の操作を既存の認証と永続保存へ接続する。切り替え時の未保存内容、取り消し・復元・保存失敗時の保持も検証する。
5. 園児IDに紐づく過去の月次計画と反省を別経路で取得し、年度や進級をまたぐ履歴も同じ園児で追う。対象月より前の3暦月を表示し、欠損を補完しない。
6. AI提案とDrive同期は利用先・送信範囲・認証・更新運用が未確定のため、接続済みと扱わない。必要な実装範囲をユーザーの依頼に合わせて具体化する。
7. 実機反映はその時点の依頼と最新の完了済み配備版に従う。今回の引き継ぎだけで配備まで実行する意味にしない。

`monthly_reflection_viewpoint` は振り返りの「観点」で、実施後の「評価・反省」と別物。`children_snapshot` と「予想される子どもの姿」も観察と予測を区別する。名前や行番号を園児IDにしない。
