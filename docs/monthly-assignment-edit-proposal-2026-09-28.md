# 月案編集を担当クラスに限定する変更案

状態：見本の試用後、「実機に反映しよう」と依頼を受け、本番（hikarinomori.hoikuict.net）が反映先と確認された。本実装と配備前検証を進めている。以下の見本の記録は当時の状態。

ユーザーの要望：「月案の編集はクラス担当を割り当てられた人が可能にする」。

## 現状の確認

- 職員管理の「担当クラス」に、職員ID・クラスID・主担当／補助／臨時・開始日・終了日を登録する仕組みがある。複数職員・複数クラスの割当が可能。
- 月案の権限アダプターは現在、職員の割当ではなく全クラスを参照範囲に入れ、編集可ロール／管理者ロールで編集可否を判定している。担当割当と月案編集は連動していない。
- 帳票の月案は `/plans/monthly-library`。従来の月案作成・文例から作成・文書詳細の編集経路も残っている。
- 承認済み・レビュー中などの本文編集制限、改訂履歴、楽観ロック、明示保存は既にある。

## 要望の解釈・提案

1. 既存の「担当クラス」設定を使い、対象クラスへの有効な割当を月案本文の編集条件にする。主担当・補助・臨時を対象にし、同じクラスの複数担当者が編集できる案。
2. 担当外の月案は閲覧のみとする案。現在閲覧できる月案の参照・保存済み内容のPDF／Excel出力は維持する。
3. 既存の「閲覧のみ」ロールを担当割当だけで自動昇格させず、編集ロールと担当割当の両方を必要とする案。
4. 新規作成、本文・担任名・評価反省の変更、文例の追記、AI提案の適用、下書き保存に同じ制限を適用する。未保存本文の出力も編集権限を確認する。
5. 保存リクエストごとにサーバーで割当を再取得する。画面を開いた後に割当が終了・取り消された場合も書き込みを拒否し、未保存本文を画面に残して理由を表示する。保存成功とは表示しない。
6. 担当外クラスに切り替えた場合、本文は参照表示、入力・追記・保存は不可とし、担当外である理由を表示する。未保存入力の保護と、保存内容への復帰・取り消しの既存動作を維持する。
7. 承認・差戻しの権限と本文編集の権限を区別する。承認済みの本文を担当者がそのまま編集できるようにはしない。
8. 対象は月案。年案・週案・日案・児童票の権限へ一括で影響する変更はしない。

上記のうち、以下の2点は確認済み。他の細部は操作見本で確認する提案。

## 追加要望：欄ごとの保存・競合確認（2026-09-28）

ユーザーの要望：「欄ごとにできる？」。欄の異なる変更を両方保存できる動作を、まず見本に追加した。以下の確認・取消の操作は試用待ちの提案。

### 保存するタイミングと競合時の操作

1. 従来どおり「下書きを保存」で明示的に保存する。
2. 園児ごとの各欄、クラス共通欄、集団の各欄、日付ごとの行事欄、担任名をそれぞれ独立して比較する。
3. 開いた時点／最後に保存した時点の内容・自分の入力・サーバーの最新内容を比較する。自分だけが変更した欄を最新の月案へ反映し、ほかの担当者だけが変更した欄は維持する。本文と出典を一組として扱う。
4. 同じ欄に異なる変更があれば今回は保存せず、その欄だけ「保存済みの内容」と「自分の入力」を並べる。競合していない欄の入力も画面に残す。部分的な保存成功にはしない。
5. 各競合欄で「保存済みの内容を使う」「自分の入力を使う」を選ぶ。自分の入力欄で両者を見ながら文章を修正することもできる。全欄を選んで「選んだ内容で保存する」を押すと再保存する。
6. 「入力に戻る」やEscでは、入力を保持して比較画面を閉じる。勝手に一方を採用しない。
7. 比較画面を開いている間に同じ欄が再び更新されたら、再度競合として確認する。両者が同じ内容に変更した場合は一致として保存できる。
8. 本文を空欄にする操作も変更として扱う。新規月案を二人が同時に開いた場合も、違う欄の変更は一つの月案へ取り込む。
9. 他職員の変更を取り込んだときは、この見本では「ひとつ戻す」の履歴を区切る。他職員の変更まで古い内容へ戻してしまうことを防ぐ。通常の自分だけの保存では履歴を維持する。担当割当・文書状態の保存時確認は維持する。

## 本実装（2026-09-28）
