# ラズパイの職員同時利用・初回測定

2026-09-28。対象は移植済みRaspberry Pi 5 / 8GB / microSD、アプリ `2ff239ad8ed175ab7fc1ac067a038429af8ec43f`。ユーザーの想定は職員の入力・閲覧が中心。

**初期の試用目安は職員10〜20人。20人超の上限や、長時間安定利用を保証する測定ではない。** 接続したままの人数と、一斉に操作を実行する人数は区別する。

## 測定方法

- ラズパイ内の独立した一時コンテナに、取得済みデータの別コピーを配置。稼働中アプリのDBはマウントしていない。ネットワークはnone、公開ポートなし。
- 園児100人のデータに架空職員20人を追加。架空職員だけで通常のローカル認証セッションを作成。
- 配備と同じアプリイメージと復元ゲートウェイを使用。通常の認証判定、CSRF、DB操作を実行。
- 1・5・10・20人を同時スタートさせ、各人が「ホーム→連絡帳一覧→月案データ読込→月案保存」を待ち時間なしで1回ずつ実行。各人の月案は別の対象月を使用し、同一セル競合はこの性能試験の対象外。
- 合計144リクエスト、HTTPエラー0件。保存結果、SQLite integrity_check、外部キー整合性の検査も成功。
- コンテナCPU設定は2コア相当。負荷クライアントも同じコンテナ内で実行。メモリ2GiB制限はカーネル非対応のためDockerが無視した。測定前後のホスト利用可能メモリは約7GiB。
- 温度は開始前46.6℃、途中観測49.4℃、終了後47.2℃。`get_throttled=0x0`。測定コンテナは終了・削除済み。稼働環境のHTTPSヘルスチェックは正常。

## 解釈と未測定範囲

この短い一斉操作試験では20人まで処理できた。職員10〜20人で通常の入力・閲覧を試し始める判断材料にはなるが、「最大20人」という上限を示してはいない。

無操作・入力途中の待ち時間がある通常利用は、この試験の連続操作とは異なる。一方、月案画面の在席通知など、ブラウザーが定期的に送る要求は今回再現していない。

Wi-Fi・Nginx・HTTPS、ブラウザーでの描画や静的ファイル読込、パスワード照合の一斉ログイン、写真・添付の転送、PDF・Excel出力、バックアップとの重複、長時間の連続利用は未測定。今回のCPU・メモリの観測だけから、それらの容量は確定できない。

実配備はアプリ1プロセスで、SQLiteはWAL方式。WALでは読込みと書込みを並行できるが、書込みは同時に1つずつ処理されるため、保存が集中した場合の待ち時間は別途見る必要がある。[SQLite公式説明](https://www.sqlite.org/wal.html)

より高い人数の運用上限を決める場合は、想定職員数、操作頻度、許容応答時間を定め、ログイン・定期通信・帳票・保存を混ぜた持続試験を行う。アプリのプロセス数やDB設定は今回変更していない。
