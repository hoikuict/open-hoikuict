# 園用ドメイン方式の変更案・操作モック

2026-09-23。基準は配布版 v2026.9.23.5（695c60c）。`beta_setup/ui` の配備済み画面と入力項目を複製し、通信APIをメモリー内の模擬処理に置き換えた。DNS・メール・OS・本番DBへの接続はなく、CSPでも通信とフォーム送信を禁止している。

起動：`python tools/windows-domain-setup-preview/serve.py`

URL：<http://127.0.0.1:18851/>

## 要望と採用できる解釈

- 通常経路は園専用ドメイン。`lan.<園ドメイン>` のAを私設IPv4へ登録し、DNS onlyにする。CaddyはCloudflare DNS-01で公開CA証明書を用意する。
- 園外公開は別の名前（例 `app.<園ドメイン>`）。LANの直接接続は維持する。公開開始・停止ではメールの基準URLも切り替える。
- IP予約、同じLAN、端末間通信の許可は引き続き必要。一般的な構成ではhosts・端末証明書登録を省けるが、全ルーターで無設定とは保証しない。
- internalはDNS・端末管理ができる担当者向け。mDNSは追加しない。
- 同一Cloudflareアカウントでも園専用の別ゾーンなら権限を分離できる。共有親ゾーンの編集トークンを各園へ配らない。
- 公開DNSへの名前照会と証明書更新に外向き通信を使う。インターネット断で園内利用が継続する保証はしない。私設IPが公開DNSに載ることを説明する。

## 表示・保存・遷移

1. PC確認・園内接続・IP予約は既存の順序を維持する。
2. 方式選択は園用ドメインを推奨。internalも選択できる。
3. 園内名・ゾーン準備・トークンを入力する。公開名は園外公開時に別入力。
4. 「名前とPC」で予定するA/DNS onlyを表示する。ここでは書かない。従来の「園内DNSへ登録した」という確認を「アプリが登録する予定の内容を確認した」へ変更する。
5. 事前確認はネットワーク、トークン有効性、ゾーン参照、レコード競合だけ。DNS編集権限の確認済みとは表示しない。未作成の名前が引けなくても、作成前の段階で必須エラーにしない。
6. Gmail・独自SMTP・受信テスト、バックアップ、最終確認は既存入力を維持する。
7. 最終適用でAを作成し、LAN DNSのA/AAAA、証明書、HTTPS、バックアップを確認する。準備確認の成功を他端末の接続成功とは扱わない。
8. 設定後は別Windows/iPadでログイン確認する。園外は携帯回線でも確認する。

入力を戻って変更すると関連する確認結果を無効にする。中断時は秘密を除く下書きのみ保存する設計。モックでは下書きを含め永続保存しない。取消はアプリ内入力を戻し、ルーターで手動保存したIP予約は戻さない。

## DNS変更・失敗時に必要な実装

- 事前確認と確定時の両方で既存A/AAAA/CNAMEを確認し、別用途のものを上書きしない。同値の既存レコードは再利用できるが所有扱いにしない。
- 作成前に操作IDと予定値を永続化し、作成後のrecord ID・内容・所有関係を記録する。応答喪失時は同じ操作の記録とコメントを照合して再確認し、盲目的に再作成しない。
- ロールバックはこの操作で作成し、その後変更されていないものだけを対象にする。APIに条件付き削除がない場合は競合を完全には防げないため、削除直前に再照合し、曖昧なら記録を残して担当者確認とする。第三者が変更したものは削除しない。
- 作成権限不足・DNS反映待ち・DNSフィルター/リバインディング保護・HTTPS失敗を区別する。保護機能の自動無効化はしない。
- サーバーPCのhosts成功を採用しない。選択した接続の各DNSサーバーへA/AAAAを照会する。

## 既存internal環境の移行（別の実装が必要）

新規LAN化の再実行では対応できない。現在の設定・認証鍵・データを維持し、バックアップ後に新しいDNSと証明書を準備する。接続を確認してから切り替え、失敗時は元の名前・設定へ戻す。旧CA/hostsの自動削除や再インストールはしない。新URLへのブックマーク変更と再ログインは案内する。

## 未確定・確認対象

新しいDNS登録の案内と、最終確定時の説明、既存環境の切替案が利用者に分かるかをモックで確認する。ここまでの画面は提案であり、本実装・本番配備済みとは扱わない。

上部で未入力・一部入力・入力済み・最終確認・既存環境の切替・園外設定を選べる。エラーは参照不可、既存レコード競合、書込み権限不足、名前解決失敗、証明書発行失敗。書込み系エラーは「適用前の確認」から模擬適用して確認する。
