# スクショ付きマニュアル 第1回確認版

利用者の「順に制作し、確認後HPへ公開」の依頼に対応する。SD-071参照。

- `review/` はローカル確認用の4手順・一覧・画像。MkDocsの `docs/` の外に置き、利用者の確認前にHPへ配備しない。
- `fixture.py` は保存済み配備系列と `test_parent_portal.py` の架空データを使う。localhost:8173、SQLiteメモリDB、通知送信なし。本番起動コードを読み込まない。
- `baseline.py` は撮影対象31ファイルと配備記録のコミットを比較する。実機の稼働版を読み直した証拠ではない。
- 新しいfixtureで `capture.cjs attendance`、`capture.cjs emergency` の順に撮影する。途中失敗で再撮影する場合は架空DBを初期化し、順番どおりに行う。別々に撮る場合も初期状態を用いる。
- `build.py` で確認ページを生成。`review/` をlocalhost:8165で配信し、`verify.cjs` でPC・スマートフォンの表示と切替を確認する。
- 撮影・検証ログ、ソース比較、進捗表の検証は `.local-dev/manual-next-20261123/` に保存する。
- 操作画像は画面または該当パネルのスクリーンショット。フォームの入力項目を削除しない。画像生成で業務画面を作らない。

公開時は利用者が確認した内容を公開ガイドへ移し、目次・検索・関連手順を更新してからstrictビルドを行う。公開状況は配信成功と公開URLの照合後に更新する。今回の原稿作成は、公開・園内アプリ更新の承認にはならない。
