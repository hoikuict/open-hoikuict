# 保護者のお知らせ・並び順の確認用モック

2026-09-27。ユーザーの依頼は「出欠連絡が優先される表示を最新のものが上に来るようにする」。
続けて「未読が優先です」と確認済み。
モック確認後、ユーザーが「本番に反映して」と依頼。実装・配備状況は
`docs/implementation-parent-notice-order-2026-09-27.md` と

## 要望と解釈

- 要望：出欠確認だけを先にまとめず、通常のお知らせと合わせて新しい日時順にする。
- 確認済み：未読を先に表示する。
- 解釈案：未読・既読それぞれの中では種類・重要度によらず日時降順。重要マークは保持する。
- 日時：通常のお知らせは公開開始日時（未設定なら作成日時）、出欠確認は作成日時。詳細を読んだ時刻は並び順に使わない。
- ホームは上位5件、一覧は全件という現行の表示件数を保持する。

## モック作成時の未確定事項とその後の扱い

1. 対象がホームの新着欄、ホームから開くお知らせ一覧、または両方か。
   配備コードではホームはすでに日時降順で、一覧は出欠確認を先に描画している。
   両画面に既読・未読を先にする処理は見当たらないため、既存仕様として断定しない。
   その後、両画面を比較できるモックに対して本番反映の依頼を受け、両方を対象に実装した。
2. ホームには未回答アンケートも混在する。モックはお知らせ6件だけを試用データとした。
   実装では既存の表示対象を維持し、未回答を未読相当として公開日時順に含めた。

## 試す

<http://127.0.0.1:8890/>

```powershell
venv/Scripts/python.exe -X utf8 tools/parent-notice-order-preview/build.py
venv/Scripts/python.exe -m http.server 8890 --bind 127.0.0.1 --directory tools/parent-notice-order-preview
```

上部でホーム／一覧、現行／変更案、未読／既読／一部既読／お知らせなしを切り替える。変更案は未読優先に固定。
日次連絡の未入力／入力済み／一部入力も切り替えてホーム全体の長さを確認できる。
通常のお知らせ・出欠確認の詳細を開くと、タブ内のみ既読になる。戻ると新しい状態で再描画する。
「次に開くとエラー」は1回だけ失敗し、既読状態を保持。戻る・再試行を試せる。
修正・取消に該当する業務入力は今回変更しない。対象外のリンクは案内を表示する。
