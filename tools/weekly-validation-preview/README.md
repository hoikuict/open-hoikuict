# 週案の保存・レビュー依頼モック r2

入口：`http://127.0.0.1:8101/edit-0.html`。本番基準は `9549c0c88a2f50028f8c5a01944f88b8e7197a13`。

0〜5歳の編集・文書詳細・週案カレンダーの18画面。配備テンプレートと週案JSを使い、全入力項目を保持。`build.py` がレンダラーへ確認用アダプターを挿入する。業務ソースは変更しない。

r2は下書き保存の右隣にレビュー依頼を追加。選択中の週の期間を表示し、その週だけを仮保存・仮依頼する。成功時は編集画面に留まりレビュー待ちを示す。文書詳細からの依頼・取り下げも維持。ほかの週の未保存入力は、詳細へ進んで編集画面へ戻る間もタブ内に保持する。これらは試用案であり、最終合意前。

「作成者を消した場合」→「レビュー依頼」で不足案内を試し、理由を押して作成者を入力すると依頼できる。「レビュー依頼エラーと再試行」は最初だけ仮依頼が失敗し、次は成功する。両入口で同じ作成者検査を使う。計画本文の必須範囲は未合意なので新たに必須化していない。

通常の見本は作成者「見本 はなこ」を保持する。保存ボタンに近い不足一覧を試すには「作成者を消した場合」または「別の週の作成者不足」を選び、下書き保存を押す。別週の不足を押すと該当週の作成者へ移動する。表示月・対象週の不足、保存済みの別職員名、通信失敗・再試行も試せる。

保存はこのタブのsessionStorageのみ。月またぎの週も同じ仮記録を参照する。「見本を入れ直す」と状態切替はその年齢の仮保存を消す。入力欄で年齢・週を変える通常操作とは別。CSPでネットワークと通常フォーム送信を禁止する。参考例、月案への接続先、職員、クラスは架空。

印刷、帳票一覧、月案本体、競合制御、権限判定、実DB、通知は試用対象外。レビュー・取り下げは仮記録で導線だけを試す。版履歴表示は見本。レビュー時の計画本文の必須条件は相談中。

`verify.py` は全静的入力欄・ボタンの隣接・外部資産不使用・CSPを確認する。r2のブラウザー証跡は `browser-verification-r2.json` と `verified-r2-*.png`。`browser-verification.json` と版名なしの画像は初版の証跡であり区別する。生成し直したら必要な照合を再実施する。

合意・実装・配備の状態は `docs/weekly-validation-preview-2026-11-15.md` と `docs/spec-decisions.md` の SD-056 に分けて記録する。
