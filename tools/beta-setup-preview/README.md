# β版「かんたん導入」確認用モック

**後続作業：** モック確認後の「実際にためそう」に基づく実装は [beta_setup](../../beta_setup/README.md)。このフォルダーは引き続き操作確認用の静的モックで、以下は提案時点の記録。

2026-09-22の「手順が複雑なので省略・対話化したい」という依頼に対する**提案と操作モック**。実際のインストーラーではない。ユーザーの操作確認後に実装範囲を決める。

## 要望・解釈・未確定事項

- 要望：Windows 11／Ubuntu 24.04 LTSへ、詳しいコマンドを読まずに導入したい。
- こちらの解釈：利用者のPCには実行環境を含む配布物を渡し、通常の入力は名前・メール・パスワード・確認の4項目にする。設定生成と初期管理者の作成・有効化はアプリ側で連続して行う。
- 仮の対象：1台で架空データを試し、その後に園内利用へ進む導入。施設利用が最初の対象かどうかはユーザーへの確認中。
- 未確定：配布形式、署名・配布経路、Ubuntu Serverの扱い、常駐・OS起動時の起動、施設向けのHTTPS・SMTP構築範囲、エラーからの再開・取取消の実装方式。

本番配備記録の基準は `5dec9cf`、開発側の手順書基準は `7cafb09`。新しい導入画面なので既存の対応画面はない。既存のCLIと職員有効化フォームにある項目・認証処理を参照した。モックから稼働環境には接続しない。

## 利用者の操作を減らす案

| 現在の手順 | 導入アプリでの扱い（提案） |
| --- | --- |
| Git導入、clone、版の切替 | 確認済みのソース・版を配布物へ含める。利用者はGit不要 |
| Python導入、venv、pip | Pythonと必要なライブラリを同梱。利用者による個別導入をなくす |
| 設定コピー、鍵生成、環境変数 | 専用の保存先・プロセス環境を構成し、初回のみ固定鍵を生成 |
| CLIで6項目に回答 | 名前・メールを通常入力。IDはメールを既定値にし、理由・実行者・承認者は確認可能な詳細設定へ |
| 有効化コードの転記 | インストーラー内部で一度だけ受け取り、本人のパスワード設定へ接続する |
| 起動・停止コマンド | アイコンから起動し、ブラウザーを開く。停止ボタンを用意 |
| 詳細な導入マニュアル | 通常利用者には1ページの始め方。詳細資料は保守・トラブル対応用に残す |

Python等の同梱は技術的に可能で、例えば[PyInstallerの公式説明](https://pyinstaller.org/en/stable/operating-mode.html)にこの配布方式がある。ただし、これは本アプリでの実証結果ではない。[OSごとに個別にビルドする必要](https://www.pyinstaller.org/en/stable/usage.html#supporting-multiple-operating-systems)があり、同梱するテンプレート・静的ファイル・DB・依存ライブラリを含めた実機確認が必要。採用ツールは未決定。

## 画面と保存のタイミング

1. **準備**：OSは実装時に検出する案。既定の保存先を表示し、必要な場合だけ変更。実装時には保存先・空き容量・既存環境・ポートを確認する。ここでは何も保存しない。
2. **管理者**：名前、メール、パスワード、確認を入力。詳細にログインID・作成理由・実行者・承認者を残す。「確認へ」で検査し、まだアカウントを作らない。
3. **確認**：入力した情報、実行者と承認者を確認。「戻る」「変更」で入力を保持したまま編集する。「準備をはじめる」で初めて作成する案。
4. **進行・完了**：準備・初期データ作成・初期管理者・起動確認を表示。最後に起動ボタンを出す。所要時間は実測値ではなく模擬表示。

このPCで本人が行う試用では、実行者・承認者の既定値は入力した管理者名とし、確認画面に表示して本人が内容を確認する案。既存の `InitialAdminBootstrapAudit` の項目は削除しない。施設・法人の承認を取得したことをこの既定値で代用しない。別の担当者は詳細設定で入力できる。

入力パスワードはモックのページメモリーだけに置く。ローカルストレージ・Cookie・ファイル・ログへ保存しない。再読込で消え、完了・ページ離脱時に状態上の値も消す。将来の実装でも秘密値をコマンドライン引数やログへ出さない。

## 状態・取消・エラー

- 画面上部の確認専用欄でWindows／Ubuntu、未入力、一部入力、入力済み、入力エラー、準備中のエラー、既存環境を切り替えられる。
- 戻る・変更では入力を保持する。再読込・「はじめから」で初期化する。ブラウザーを閉じた後の下書き復元はしない案。
- 入力エラーは該当欄と要約へ表示し、先へ進めない。モックのパスワード検査は文字数・一致のみ。実装では既存の認証ポリシーを呼び出す。
- 中断は確認ダイアログを挟む。進行表示中はダイアログを開くと模擬進行を止め、中断後は確認画面へ戻れる。
- 書込み不可は、未確定の状態で止まった例として表示する。保存先の修正・再試行ができる。実装時の失敗箇所別の退避・再開方式は未確定。
- 既存環境では新規管理者・鍵を作り直さず起動へ進む案。新規試用は別の保存先を用意する。既存環境の上書き・更新・DB巻戻しボタンは設けない。

## 実装時に省略できない処理

利用者の手入力は省けても、パッケージ整合性・保存先の保護・秘密鍵の作成・パスワードのハッシュ化・既存環境の保持・起動検査は必要。

実装では、以下をモックとは別に設計・検証する。

- 対象OSごとの配布物とPython 3.12、テンプレート・静的資産・文例DB・動的import・ライセンス情報。
- 既存環境変数の影響を受けない専用プロセスと、読取専用アプリ領域／書込可能データ領域の分離。
- 既存の `bootstrap_admin`、`activate_staff_password` を経由する監査・認証。有効化コードの安全な内部受渡し、途中失敗で重複作成しない制御。
- 初回だけ接続可能な導入処理、loopbackへの限定、外部からの初期管理者作成防止、CSRF・セッション・パスワード保護。
- 確定前の準備場所、作成中断・失敗後の状態判別、未完了からの再開。既存データの自動削除を避ける。
- インストール済み環境での再実行・二重起動、OS再起動後の動作、書込み拒否、ポート使用中、ディスク不足。
- 施設利用のHTTPS・SMTP・常駐・バックアップ・復旧。これらを省略した設定を施設向け完成品として提供しない。

## モックを開く

`index.html`・`style.css`・`wizard.js` のみの静的ページ。本番アプリを起動する必要はない。リポジトリ直下から、例えば次で表示する。

```powershell
.\venv\Scripts\python.exe -m http.server 18846 --bind 127.0.0.1 --directory tools/beta-setup-preview
```

ブラウザーで `http://127.0.0.1:18846/` を開く。初期管理者CLI・pip・アプリ起動・データ削除は呼び出さない。CSPでも接続とフォーム送信を禁止している。

## この案での「始め方」

配布アプリの実装後に、通常利用者へ次の1ページを渡すことを目指す。現時点ではダウンロードできる導入アプリは未作成。

1. お使いのOS用の「オープン保育ICT」をダウンロードして開く。
2. 名前・メールアドレス・パスワードを入力する。
3. 内容を確認し、「準備をはじめる」を押す。
4. 完了したら「起動して開く」。次回からは同じアイコンを開く。

確認してほしい点：3画面で分かるか、通常の4入力で十分か、詳細設定の場所、園内利用をどの段階で扱うか。
