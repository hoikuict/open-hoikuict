# 園内接続の案内を分割する操作モック

`python serve.py` → http://127.0.0.1:18850/

実インストーラーの園内接続画面を8手順に分割した提案。現行の全入力を維持し、前後の導入フローも試せます。`guide.js` が元のモックの園内接続画面だけを拡張します。

静的ファイルだけをloopbackに配信します。API・DB・送信・OS変更はありません。状態はページ内だけに保持し、ネットワークの検出や確認結果はすべて架空です。本物の秘密情報を入力しないでください。

- 初期表示：準備の見通しから。
- 「試す状態」：未入力、一部入力（住所の固定）、入力済み（準備の確認）、導入ホーム、LAN利用中、園外利用中。
- 「試すエラー」：DNS、トークン、IPの不一致を準備確認で模擬。元のメール・バックアップ・適用エラーも保持。
- ドメイン／園内専用の両方、戻る・中断・再開・取消・修正後の再確認を試せます。
- 担当者への依頼文は表示だけです。送信・クリップボード操作を自動実行しません。

仕様：`docs/windows-lan-guide-proposal-2026-09-23.md`。実インストーラー・配布EXEへの変更は、この案の試用と合意後。

## 2026-09-23 操作確認

- 園内専用方式：接続の確認、IP予約、方式選択、名前、証明書準備、DNS、準備確認、既存メール画面への遷移を実ブラウザーで確認。
- ドメイン方式：入力済み例の確認、トークンのエラー、説明3段階の戻る・進む、必要項目の表示を確認。
- 未確認時に先へ進まないこと、DNSエラーから再試行して進めることを確認。
- 相談文表示、中断・同じ手順からの再開、取消後に導入済み状態を保持してホームへ戻ることを確認。
- JavaScript構文とブラウザーコンソールを確認。実ネットワークの成功を示す検証ではない。

## Gmailの追加案

http://127.0.0.1:18850/#mail からメール選択画面を試せます。Gmailの定型値、2段階認証、アプリパスワード、確認メールの受信までを順番に案内します。

架空のアドレス・パスワードの入力ボタンを用意しています。Googleの設定や実メール送信は行いません。「試す状態」にはメールの未入力・一部入力・入力済み、「試すエラー」にはGmail認証失敗を追加しました。

実ブラウザーで、Gmail選択→5手順→模擬送信→受信確認→バックアップ画面への遷移、認証エラーからの修正・再試行、送信元変更によるGoogle確認の無効化、ほかのSMTP用全入力欄の保持を確認しました。
